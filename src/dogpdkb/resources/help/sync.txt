# Whole-batch sync contract

sync needs no manifest argument: it validates the complete source listing and
executes whole-batch discovery, downloads, comparison, fixed planning, OCR,
corpus publication and native Graphify compilation. It never publishes the Web.
--resume accepts the same saved run instead of starting discovery again; the
source, subscription, corpus and graph targets must still match. --stop-after
plan pauses after complete raw inputs/comparisons and the fixed plan, before
OCR, corpus and graph writes. Remove that option on resume to continue.

Authored-body routing uses the offline public mdcompare semantic CLI:
NEW/CHANGED/UNCERTAIN -> COMPILE; demonstrated EQUIVALENT -> reuse/metadata;
UNAVAILABLE -> DEFER. Authored deletions compile. Image/OCR changes, errors and
results are advisory, never body vetoes or reasons to promote equality. Uncertain
usable body evidence compiles without a model or manual review. Full durable
semantic diff/index sidecars live outside wash under state/<book>/semantic/<run>.
Optional [paths].body_recovery names explicit mdcompare-body-recovery-1 repairs,
resolved from config and frozen with byte witnesses per run. Resume validates
saved repair inputs; it never silently replaces them with live config changes.
See apply --help --full for schemas, source versions and successful-baseline rules.
This routing does not change Graphify's text-input projection below.

--concurrency N applies only to document exports. It accepts 1, 2 or 3, defaults
to 2 and never permits more than 3 in-flight exports; 1 selects serial downloads.
Invalid values fail before run creation or tool calls. Exports remain independent
Skylark CLI processes. Only the main coordinator records settled results and
checkpoints. One export failure does not stop other eligible downloads; identity,
version and same-version suppression checks remain mandatory. The whole download
batch settles before comparison; listing, comparison, OCR and Graphify retain
their current stage order and concurrency.

On --resume, a different --concurrency does not invalidate completed downloads or
authorize a suppressed retry. SIGINT/SIGTERM stops all in-flight export process
groups, starts no queued exports and preserves truthful checkpoints. The option
is per invocation, not a TOML setting or a Skylark argument. --retry-graph skips
downloads entirely, regardless of --concurrency.

Graphify inputs
--graphify-inputs {all,text} defaults to text: Graphify scans a run-owned mirror
containing only Markdown (.md, case-insensitive). OCR text in Markdown is kept;
images and other non-Markdown files stay in the public corpus but are not sent
for extraction. Existing scan controls are preserved. all restores the previous
complete-tree scan, including images and other resources. The option also applies
to --resume RUN --retry-graph. Native Graphify may prune old non-Markdown graph
records when switching to text; graph/cache artifacts are not manually rewritten.

```text
dogpdkb sync --config instance/dogpdkb.toml --book funds --stop-after plan --concurrency 3
dogpdkb status --config instance/dogpdkb.toml --book funds --run RUN --json
dogpdkb sync --config instance/dogpdkb.toml --book funds --resume RUN
```

stdout JSON has exit_code (0/1/2/130/143), paused (boolean), manifest (absolute
dogpdkb-compile-1 JSON path or null), and run (absolute run.json path). Reports
are reached through run.artifacts. Inputs and full-source witnesses required
after cleanup live outside wash. A failure before a result can emit stderr only.
--help --full on discover, apply and update-graph describes their stage schemas.

Only successful OCR is reused by its tool. Downloaded raw versions, published
corpus and successful graph versions remain separate facts. Source export and
OCR failures are isolated where possible; usable bodies may still compile and
produce exit 2. A shared graph failure can make the entire batch exit 1. Inspect
failures and per-document reports; numeric exits alone do not grant retry.

Stopped plans and interrupted/failed runs retain evidence. Saved input copies
are checked before and after OCR and again before publication. Missing/changed
inputs require a fresh plan, not automatic redownload. Completed/partial sync
cleans successful wash copies; ordinary resume is unavailable after cleanup. Durable
failure/unknown suppression remains after purge. An agent must diagnose failures
before arranging new work; ordinary repeated sync does not repair them.

After diagnosing and fixing a graph failure, explicitly retry only that stage:

```text
dogpdkb sync --config instance/dogpdkb.toml --book funds --resume RUN --retry-graph
```

--retry-graph requires --resume and cannot use --stop-after. It uses the saved
final compile manifest, even after cleanup, without repeating discovery,
downloads, comparison, OCR or corpus writes. Only this run's failed/unknown or
abandoned in-flight graph versions in that manifest are authorized. Other
blocked sources still stop compilation. Original target locks, version/metadata
checks and byte witnesses remain mandatory. No block is cleared before a real
successful result. Each attempt keeps a separate report; earlier failures stay
recorded and can keep the run partial. This is explicit operator recovery,
not an automatic daily retry or a way to recover missing/changed inputs.

After a comparison/routing fix, recompute the saved published batch explicitly:

```text
dogpdkb sync --config instance/dogpdkb.toml --book funds --resume RUN --retry-graph --replan
```

--replan requires both --resume and --retry-graph and rejects --stop-after. It
requires the saved original plan plus its complete raw/baseline snapshots, even
if a final published manifest survived cleanup. It validates identities, current
published versions/targets and byte witnesses before comparison and again before
using the revised selection. Comparisons use run-owned copies of the original
snapshots, never the already replaced corpus as its own baseline. Each replan
keeps a separate directory and preserves previous reports/manifests. Only actions
and reason codes change in the compile manifest; published corpus, OCR output and
its elapsed budget remain unchanged. Missing/changed originals require a new
plan. This opt-in recovery does not reset graph failure suppression or enable an
automatic same-version retry.
