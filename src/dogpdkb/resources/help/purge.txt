# Explicit wash deletion

Specify exactly one of --run RUN and --all. An ID must identify a direct run-*
directory inside this selected book's wash; directory and run.json references
must resolve to the same permitted scope. Parent traversal, symlink wash/run
paths, symlink run metadata, and overlap with protected state/corpus/graph/cache
are rejected. All candidates are checked before deletion starts.
Saved schema, book key/source URL and run ID must match the selected wash.
Changed corpus/graph execution targets do not prevent deleting an owned run;
resuming execution still requires its frozen targets to match configuration.
Saved corpus/graph targets must be absolute paths and must not overlap any
selected run. Purge holds both current and saved target locks through all
deletions, even when the saved parent PID has exited. Missing historical target
directories stay absent; existing ones may receive a missing .dogpdkb.lock file.
Existing saved lock contents are preserved.

Default permits completed/partial runs only. --force also permits discarding
paused, failed or interrupted work, permanently losing that run's saved plan,
failure Markdown, local images, reports and status evidence. It never permits
deleting a still-running run or bypassing the held corpus/graph locks. Deletion
can fail partway due to filesystem errors; no rollback or automatic retry exists.

stdout schema is an object with book (selected key) and purged (absolute directory
path array). An empty --all selection succeeds with []. --run for a missing
directory fails; a repeated --all returns remaining candidates only. No remote
tools or model calls occur. Persistent inputs, durable facts/suppression, corpus,
published graph and tool caches remain. Purge is not failure recovery or reset.
