Semantic score route (semantic-route-1.0)
========================================

mdcompare semantic-route --report REPORT.json --diff-index DIFF.json
                          --scores SCORES.json --output ROUTE.json
                          [--compile-threshold 1..5] [--skip-ambiguity-intercept yes|no]

The report must be semantic-1.0, the index mdcompare-semantic-diff-1 and
index.report_sha256 must match the exact report bytes. Score input schema:
{"schema_version":"mdcompare-semantic-scores-1","diff_index":"diff.json",
 "scores":[{"knowledge_base":"book","document_id":"42",
 "evidence":"evidence/000000.json","evidence_sha256":"<sha256>",
 "score":1,"ambiguous":false}]}
Each score identifies exactly one indexed sidecar by the same relative evidence
path and its SHA-256 digest over exact sidecar bytes as recorded in the index. Duplicate, malformed,
non-integer/out-of-range score, missing identity, escaping evidence path or bad
binding rejects the entire invocation and publishes nothing. Score paths are
relative to the score manifest; evidence paths are relative to the diff index.
The referenced file must resolve inside index.evidence_directory.

Only deterministic CHANGED/COMPILE authored-body results use scores. Strictly
score > threshold compiles; score <= threshold skips. Default threshold is 3.
With ambiguity intercept yes, an ambiguous score at/below threshold compiles;
it never changes a high-score route. No/missing scores stay COMPILE. All other
deterministic statuses keep the original route. Output is separate and does not
modify semantic-1.0 or invoke an LLM, network, Graphify or compiler. Inputs and
the indexed source manifests, Markdown paths and evidence are protected from
output aliasing.

Exit codes: 0 route report published; 1 invalid binding/input or publication failure.
