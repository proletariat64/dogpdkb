# dogpdkb 日常知识增量与 mdcompare 产品化

Status: ready-for-agent

## Problem Statement

当前正文比较器、同步工具和 Graphify 提取各自已有实现，但没有形成可审计的日常知识更新链路。正文 v3 与测试仍在工作树；日常增量核查、字符统计、模型判等和知识价值审查主要依赖临时脚本及实验。

操作者需要知道自上次观察以来究竟新增多少文档、哪些既有文档真正修改正文，以及哪些修改值得重新编译知识。更新时间变新、文件改名、正文差异、语义变化和图谱提取收益必须分开，不能再把历史候选几百篇当作两天的日常业务更新，也不能将 REVIEW 或候选直接送去整篇重提取。

同时，现有 Graphify 按完整来源替换旧记录。即使输入完整新文，模型仍可能遗漏旧限制；不能把候选发现等同于安全发布。失败、待核或仅观察到新版时，都不应提前推进图谱成功基线。

本规格把已验证的正文比较能力产品化，先解决按文档减少不必要编译，不以块级图谱重写、全量模型判等或重建历史图谱作为前提。

## Solution

保留独立、离线、只读的 `mdcompare knowledge`，复用当前 v3，不从零重写。dogpdkb 负责采集完整远端元数据、保存隔离 raw 快照、准备比较输入，并输出逐文档可审计计划。

默认流程止于采集和规划。正文可复用时保留既有知识；仅元数据变更单独处理；未知或待核时保留旧图并登记缺口。确有新侧正文候选时提供新旧依据，经过显式审核后，才允许在授权执行阶段按完整文档提取，并在隔离结果通过验证后发布。候选不自动触发 Graphify，也没有失败后整篇重跑的兜底。

分别呈现新增文档、既有正文变化、元数据变化、待核项、获准提取、缓存命中、实际模型调用、成功图谱更新等数量。安装包必须包含现有新源码和测试所对应的行为，不再依赖忽略目录中的私有脚本运行产品链路。

## User Stories

1. As a 同步操作者, I want 基于完整远端文档列表比较两次观察, so that 得到真实日常增量而非历史积压量。
2. As a 同步操作者, I want 比较窗口包含基线、开始和结束时间及其时区, so that 两天半不会被误报成精确两天。
3. As a 同步操作者, I want 按知识库和文档 ID 确认身份, so that 改名或搬动不被算成新文档。
4. As a 同步操作者, I want 分开统计 new、updated、renamed 和 moved, so that 不同处理任务不会混算。
5. As a 同步操作者, I want 重叠标签仍只导出一次, so that 不会重复下载或重复计算知识变化。
6. As a 同步操作者, I want 时间戳转换为同一时间基准后比较, so that 表示格式差异不会制造更新。
7. As a 同步操作者, I want 元数据缺失、时间倒退和列表不完整明确报错, so that 异常不会被当成无变化。
8. As a 同步操作者, I want 保存列表及详情各自的版本时间, so that 能理解非原子采集中的版本差异。
9. As a 同步操作者, I want 为本次变化保存独立 raw 快照, so that 后续能重现正文比较。
10. As a 同步操作者, I want 获取新版不自动推进成功版本, so that 待核或失败文档不会在下次消失。
11. As a 知识维护者, I want 区分采集、语料成功和图谱成功版本, so that 文档已保存不会被误认为知识已更新。
12. As a 知识维护者, I want raw 与历史富化内容的来源显式记录, so that 不用文件名猜测旧版正文。
13. As a 知识维护者, I want 图片和 OCR 完全不参与本次判断, so that 正文结果不受这些产物或配置影响。
14. As a 知识维护者, I want 明确标记的派生区域在受支持的导出包装中一致排除, so that 已知富化文字不会制造更新候选。
15. As a 知识维护者, I want 未标记文字仍按可观察正文处理, so that 系统不凭猜测删除真实规则。
16. As a 知识维护者, I want 金额、币种、主体、条件、否定、步骤顺序、URL 和表格绑定保留, so that 小而重要的修改不会被去噪吞掉。
17. As a 开发者, I want 代码围栏、缩进和字面内容受到保护, so that 统计清洗不会反过来批准错误复用。
18. As a 知识维护者, I want 同时看到复用单元与具体变化证据, so that 部分变化不导致整篇被当成新增知识。
19. As a 知识维护者, I want 旧侧缺失、上下文变化和标题变化单列待核, so that 不会误删旧知识或忽略业务范围变更。
20. As a 成本负责人, I want 候选字符、模型输入、缓存命中和实际费用分开报告, so that 不把文本量冒充真实成本。
21. As a 同步操作者, I want 正文可复用时不启动 Graphify, so that 避免无意义重编译。
22. As a 同步操作者, I want 改名和搬动仍能更新引用与目录, so that 节省编译不会留下失效路径。
23. As a 审核者, I want 每次提取都对应明确批准的文档与输入版本, so that 原候选发生变化时不能沿用旧授权。
24. As a 审核者, I want 新 ID 单独审核和计数, so that 不把新文档冒称全库新知识。
25. As a 同步操作者, I want 待核项不会自动升级成全篇提取, so that 未知不会成为成本放大器。
26. As a 知识维护者, I want 提取使用完整获准文档, so that diff 片段不会冒充完整来源覆盖。
27. As a 知识维护者, I want 发布前检查重要原有限制和新增事实, so that 新图节点变多也不能掩盖知识丢失。
28. As a 同步操作者, I want 网络和提取失败可续跑且保留旧图, so that 部分失败不会破坏已有服务。
29. As a 审核者, I want 报告有稳定版本、原因码、来源位置和守恒计数, so that 能复核自动化行为。
30. As a 安全负责人, I want 默认日志不包含正文、认证或完整私有地址, so that 产品化不扩大资料暴露。
31. As a 开发者, I want 通过现有 CLI 黑盒验证完整流程, so that 不依赖内部函数布局。
32. As a 运维人员, I want 隔离安装后的行为与源码验收一致, so that 服务器不会继续运行缺少新能力的旧版本。

## Implementation Decisions

### 组件职责与兼容

- mdcompare 负责离线正文比较和规划，不登录语雀、不下载资源、不执行 OCR、不调用模型、不推进基线、不合并图谱。
- dogpdkb 负责发现变化、准备不可变输入、执行明确授权的文档操作、维护进度和发布状态。
- 继续使用现有清单、CLI、Graphify 文件级缓存及整来源合并能力；保留旧严格 `compare` 的契约，不把图片/OCR复用动作混入新正文流程。
- 新能力必须进入可安装包及正式命令，不依赖某次实验日期、绝对机器路径或私有临时脚本。无需将全部研究脚本转成产品功能。
- 本规格规定开发和验证工作，不授权现在改变生产任务、调用付费模型、更新图谱或推进生产基线。实际部署和执行沿用独立授权边界。

### 远端发现与日常窗口

- 身份为知识库加文档 ID；名称、日期和目录不参与身份判定。
- 使用完整远端列表及精确内容时间戳。按现有上游规则在缺少内容时间时使用可用的更新时间，同时记录实际使用字段；都不可用时列异常，不能声称无变化。旧无状态数据的日期回退只作为显式历史限制，不能用于证明精确窗口内的知识变化。
- 分类标签允许重叠，导出和结果按 ID 去重。分别记录元数据分类和正文比较结果，不把 updated 当作正文变化。
- 列表未出现的旧 ID 只能标注缺席；沿用现有删除策略，禁止单凭本次比较推断删除。列表不完整不得形成“零删除”“零更新”的成功结论。
- 保存采集起止时间、页覆盖、唯一 ID 数、失败和完整性状态。分页超时沿用有界重试与检查点；失败页不得静默跳过。
- 列表与详情时间不一致时分别保存，不伪造原子快照；后续比较与授权绑定实际导出的正文版本。采集期间再次变化必须形成可见的版本说明或待核项。
- 常规增量查询只处理近期变化；不回填历史有意过滤的缺失文档，不修改日期截止政策。

### 快照和成功基线

- 区分三个概念：本次观察快照、已成功发布的语料版本、已成功应用的图谱来源版本。复用已有状态和文件能力，不另建重复索引。
- 日常变化量相对指定观察快照统计；图谱是否需要更新则相对图谱最后成功应用的来源比较，不能因为语料已保存而跳过尚未应用的知识。
- 保存完整观察元数据，raw 只按所选文档导出，未重导出的文档可引用已存在的成功快照。清单必须明确引用和内容阶段，不能把历史富化副本伪称 raw。
- 初次没有完整观察基线时输出基线初始化状态，不把全库文档算成一天新增，不自动全量导出或提取。
- 下载完成只表示采集成功。待核、拒绝、失败和未获授权文档保持 pending，其图谱成功版本不前移；下次扫描即使远端时间没再变也必须保留待办。
- 仅元数据维护成功可更新相应元数据记录，不冒充知识重提取成功。正文复用且元数据工作完成后，可记录已覆盖的等价新来源及比较规则版本，但不得声称发生模型提取。
- 输入发生变化时旧比较和批准失效；优先通过不可变快照及直接比较实现绑定，不为此默认新增哈希、指纹或持久向量索引。

### 正文视图与规范化

- 以当前 v3 的章节、段落、列表、表格、代码和上下文对齐为起点，保留有限展示归一化、数量等价及来源位置。
- 显式排除图片引用及明确有界的 OCR 派生区域，不检查图片、不读取识别结果作证据、不生成相关任务，也不以资源缺失阻塞正文结果。
- 对代码包装中的明确工具生成区域，必须同时满足排除派生内容与保护普通字面代码。不能复制统计脚本“去围栏、反引号、全部左缩进”的做法作为正式等价算法；不能无条件删除代码示例中的同名字符串。
- 边界不完整或来源位置不足以安全识别时保留旧知识并明确限定可比较范围，不猜测未标记文字来源，不把被丢弃的尾部默认判为等价。
- 单元比较和统计共享经验证的正文范围规则。展示型字符估算可有额外归一化，但必须标注其用途，0 diff 不成为单元复用的额外授权。
- 保留金额、比例、币种、主体、条件、否定、URL目标、代码字面值、表格行列绑定和有序步骤；相似度只找候选，不能批准语义等价。
- 当前受限跨文档复用仍遵守同知识库、主体、路径、单元类型和上下文证据要求，不引入全库模糊判等。

### 规划和执行权限

- 保留 `REUSE`、`DELTA`、`REVIEW`、`NO_BODY`、`UNKNOWN` 及独立 `graphify_plan`。比较结果保持只读，`plan_only`、禁止自动提取及禁止全篇回退的既有含义不变。
- `KEEP_EXISTING` 保留旧知识；有元数据任务时仍执行必要的元数据维护。`HOLD_EXISTING` 保留旧知识和待办，不默认调用模型。
- `BODY_DELTA_CANDIDATE` 只生成复核材料，包括实际新侧单元、旧侧证据、上下文和来源版本；不是提取许可。
- 新 ID 单列文档新增，不声明全库知识新增。没有已有图谱时，不能把 HOLD 解释成已有知识已覆盖。
- dogpdkb 的执行许可与比较结果分离：明确批准所选身份、当前 raw 版本和整来源替换范围后才能提取；任何 REVIEW 的删除、上下文和旧规则保留问题必须明确处置，不能只批准“有候选”就跳过这些问题。
- 首版不实现自动模型语义判等。对保守规则无法确认的情况，输出可复核依据并保持待办；不以默认 LLM 或整篇重提取掩盖缺口。

### 完整来源提取与发布

- 获准执行的文档使用完整、冻结的新来源；diff、正文候选块和展示型统计视图不得冒充完整来源送入现有替换接口。
- 元数据改名或搬动需维护稳定身份到来源引用的对应关系，避免产生第二份知识；若现有接口不能安全更新来源，明确挂起，不靠重编译规避。
- 复用既有 Graphify 文件级缓存。分别统计获准文档、实际缓存命中和实际外部提取；输入文档数不等于调用次数。
- 提取结果先写隔离输出，验证所选完整来源覆盖、节点身份和边引用完整性、输入版本、已确认新事实和固定旧限制，之后才进入既有发布事务。
- 验收失败或发现重要旧限制丢失时保留原图及成功基线，不因为节点增多或提取退出码为0就放行。固定问题集是有界质量门槛，不宣称证明全部知识无损。
- 未批准的旧事实删除、未确认的来源缺失不能静默应用。只有已有来源替换契约和审核范围均成立时才调用整来源更新，不引入片段补丁或自动事实级拼接。
- 正式发布与状态写入沿用现有成功边界；支持逐文档结果、检查点和幂等续跑。图谱已更新但状态写入失败时必须可识别和恢复，不得把半成功描述成全部完成或静默重复计费。

### 报告、错误和交付

- 保留 knowledge-1.0 的既有字段和退出码；不兼容扩展必须版本化。dogpdkb 输出单独版本化的流程报告，避免把阶段结果混入比较状态。
- 每个所选 incoming 身份恰好一个比较/错误结果；基线独有身份单列。标签重叠计数与唯一文档计数分别说明，候选、批准、执行、成功和待办可核对。
- 分别记录字符估算、实际 token、实际调用、缓存证据与费用来源；没有使用量记录时明确未知，不推算真实账单。
- 默认日志只含必要身份、计数、状态和原因；正文证据显式启用、有界、私有权限。认证、凭证和私有正文不得进入公共日志、测试夹具或可提交报告。
- 报告原子写入，异常不能留下伪完整成功产物。复用原有只读保护，不覆盖输入和已有验收产物。
- 通过仓库要求的检查、构建和隔离安装；验证独立 CLI 及 dogpdkb 调用的是同一交付版本。部署验证不自动授权生产同步。

## Testing Decisions

- 用户已确认验收入口：以现有 CLI 黑盒为主，先验证独立 mdcompare，再从 dogpdkb 同步入口验证分类、提取选择、失败恢复和状态推进；不新增内部测试接口。
- 复用已有临时目录、清单、输入保护、子进程 runner 替身、Graphify 合并测试和安装冒泡测试。语雀及 Graphify 在自动化中使用受控替身，不进行真实网络、OCR或付费提取。
- 好的测试检查外部结果、原因码、明确允许的副作用和未发生的提取/发布，不断言函数布局或仅复刻编辑文本。
- 必测同字节正文但时间戳变新、两种等价时间表示、新 ID、改名/搬动、标签重叠、缺失/倒退时间、分页失败、详情晚于列表，以及非完整列表不能判零变更。
- 必测观察基线缺失、旧 raw 缺失、语料成功而图谱待核、远端未再变化但 pending 仍被保留、采集失败不推进成功版本。
- 必测安全展示归一化及其反例：条件与否定、金额/币种、不等号、URL、表格绑定、步骤顺序、代码缩进和字面值必须保留。
- 必测明确生成区域在受支持导出包装中的排除、同名字面代码保留、不闭合边界和未标记文字的保守行为。不验证图片内容或 OCR 质量。
- 必测 KEEP 不提取、HOLD 不提取、候选未经批准不提取、元数据操作不重复提取、新文档不自动全库判重、批准后输入变化使许可失效。
- 必测获准提取传完整 raw 而非 diff；缓存命中不计外部调用；来源缺失、无效边、关键旧限制遗漏或质量门禁失败时不发布、不前移图谱成功版本。
- 必测逐文档部分失败、检查点恢复和图谱提交/状态记录之间故障，防止丢待办或静默重复付费。
- 真实日常 UAT 使用已冻结的11月7日与9日快照：7,548到7,550个ID；2新、4时间变新，其中1原文完全相同、3正文变化。该集合只作固定输入回归与有界业务核验，不要求所有数据具有相同过滤率。
- 从三篇已核查正文修订和既有知识限制构造私有固定问题，校验正确主体、条件、否定、责任与操作要求。把设计文稿变化与现网能力分开，把来源事实与模型提取波动分开。
- 自动化测试不默认调用真实 Graphify。后续真实隔离编译需另行授权，输出目录、输入集合、费用和生产未修改证据明确记录；先前十篇冒泡不能替代本规格的正式流程验收。
- 最终验证包含完整CLI调用、报告守恒/确定性/隐私、输入保持、安装一致性和仓库门禁，不以候选数下降或图谱节点增加作为通过标准。

## Out of Scope

- 图片检查、图片下载、OCR执行、OCR质量评估及OCR复用能力扩展。
- 将旧严格比较契约改写为新的正文业务契约。
- 新建生产LLM判等服务、完成历史Kimi全量实验、固定某个模型或默认花费策略。
- embedding、全库模糊语义去重、向量库、新增持久指纹索引。
- 将收益不足的残差/HTML原型强行产品化。
- Graphify 块级来源覆盖、diff补丁、事实级自动合并及语义删除。
- 全量重建生产图谱、历史回填、自动停止/重启生产同步或擅自推进基线。
- 修改Graphify查询渲染、建设语义问答或新的前端；本规格仅通过现有可观察输出核验交付事实，检索产品缺口另立范围。
- 根据小样本宣布全量准确率、固定日均更新量、真实节费比例或已上线业务能力。

## Further Notes

- 当前源码盘点见 [实现与实验边界](../../docs/mdcompare-implementation-status.md)。正文判定沿用并补齐 [knowledge 契约](../pre-ocr-content-dedup/knowledge-spec.md)，不撤销旧严格比较验收。

- 现有模型和十篇提取实验说明比较误报与知识覆盖补充均真实存在，也观察到旧限制丢失。它们支持保守门禁，不支持批量覆盖生产图。
