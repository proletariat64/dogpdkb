# dogpdkb 统一无人值守阶段同步

Status: ready-for-agent

## Problem Statement

dogpdkb 将默认同步与 knowledge 同步分成两套行为，扫描、比较、OCR、审批、编译的入口和输出方式不统一。操作者难以确定任务运行到哪里，也难以在同一批次停止、恢复和复用已下载文档。

日常任务需要通过 crontab 长期无人值守执行。当前过重的人工审批、知识质量门禁，以及依赖外部 token、额度和不稳定输出的 OCR，都会使每日更新等待人工处理。历史 wash 工作目录与临时产物长期保留，又造成空间占用和恢复依据不清。

本工具优先保证每天完成并产出可用知识库。模型提取导致的知识数量和语义质量差异属于后续质量问题，不能成为每日任务的人工阻断点。异常应被可靠记录，由后续定时 agent 汇总，决定重做或放弃。

## Solution

工作入口统一为 dogpdkb sync，固定整批执行 capture、mdcompare、plan、ocr、graphify compile 五个阶段。每个阶段完成后再进入下一阶段，不按单篇文档贯穿所有阶段，不引入工作流引擎、队列或常驻调度服务。

capture 完成扫描、文档打标、下载选择和有效原文复用；mdcompare 完成本批比较；plan 汇总比较结果并自动确定后续工作；ocr 尽力完成本批图片识别；graphify compile 使用已准备好的内容编译并发布成功结果。OCR 不完整不阻断正文编译。

sync 主动写入轻量运行状态和持久批次结果。dogpdkb status 只读查询，watch 反复调用该命令即可。crontab 负责定时，shell 负责日志重定向，系统 logrotate 负责日志轮转。

每次结束前归档异常及必要输入；后续成功结束自动清理旧工作目录。日常 sync 不无限重试历史异常，定时 agent 根据持久结果另行处理。

## User Stories

1. As an 运维人员, I want 只配置一个 sync 命令, so that 无需在默认与 knowledge 两套流程之间选择。
2. As an 运维人员, I want 通过 crontab 每天启动任务, so that 不需要常驻调度服务。
3. As an 运维人员, I want 使用显式配置和绝对路径运行, so that cron 环境与交互终端具有相同目标。
4. As an 运维人员, I want 前一任务仍运行时拒绝重复启动, so that 并发任务不会写坏状态或重复计费。
5. As an 操作者, I want 五个阶段整批依次完成, so that 能清楚判断任务推进到哪里。
6. As an 操作者, I want 在指定阶段结束后停止, so that 能先检查采集结果或执行计划。
7. As an 操作者, I want 按原批次恢复, so that 不丢失已完成阶段和有效产物。
8. As an 操作者, I want 远端文档按知识库和文档 ID 识别, so that 改名和搬动不会变成重复新增。
9. As an 操作者, I want 同时看到新增、时间更新、改名、搬动和缺席标签, so that 能理解本次采集选择。
10. As an 操作者, I want 同一文档的重叠标签只触发一次下载, so that 不浪费接口调用。
11. As an 操作者, I want 同版本有效原文被自动复用, so that 以前 UAT 或同步已下载的 Markdown 不会再次下载。
12. As an 操作者, I want 缺失或版本已变的原文重新下载, so that 复用不会掩盖真实更新。
13. As an 操作者, I want 只同步近期变化, so that 不自动回填被有意过滤的历史缺失文档。
14. As an 维护者, I want updated 与正文变化分开记录, so that 更新时间变化不会必然产生知识重编译。
15. As an 维护者, I want 明确可复用的正文保留已有知识, so that 减少重复编译。
16. As an 维护者, I want 新文档和比较不确定的文档自动进入完整文档编译, so that 任务不等待人工审批。
17. As an 维护者, I want 图片处理与正文复用独立判断, so that 正文未变时仍能处理变化的图片。
18. As an 维护者, I want 每篇文档的自动动作具有原因, so that 不需要审批系统也能事后解释结果。
19. As an 运维人员, I want 没有工作量的阶段正常跳过, so that 无更新的每天也能结束。
20. As an 运维人员, I want OCR 成功结果持续复用, so that 避免重复调用和识别波动。
21. As an 运维人员, I want OCR 单张失败不阻断其他图片, so that 本阶段仍能取得有效结果。
22. As an 运维人员, I want token 无效或额度耗尽时结束 OCR 阶段, so that 任务能继续编译正文。
23. As an 运维人员, I want OCR 阶段具有有限等待和时间预算, so that 外部接口不会无限占用当天任务。
24. As an 维护者, I want 无效或失败 OCR 不覆盖既有成功结果, so that 不稳定接口不会破坏有效缓存。
25. As an 维护者, I want 编译使用本批实际准备好的正文和有效 OCR, so that 缺少图片文字仍能发布可用知识。
26. As an 维护者, I want 编译失败来源保留旧知识, so that 单篇失败不会清空既有服务内容。
27. As an 运维人员, I want 通过 status 查看阶段、计数和最近进展, so that 不必分析外部工具原始日志。
28. As an 运维人员, I want 状态能识别退出进程, so that 崩溃后不会永久显示 running。
29. As an 运维人员, I want stdout/stderr 可以直接追加到普通日志文件, so that 系统日志工具就能完成保存和轮转。
30. As an 运维人员, I want 阶段详细输出落盘, so that Graphify 或 OCR 失败时仍有诊断依据。
31. As an 运维人员, I want 旧成功批次自动清理, so that wash 不会随着每日运行持续膨胀。
32. As an 运维人员, I want 暂停批次与有效长期缓存不被清理, so that 可以恢复并避免重复下载。
33. As an 异常处理 agent, I want 扫描结构化历史结果, so that 能收集异常文档和 OCR 项。
34. As an 异常处理 agent, I want wash 清理后仍能读取异常必要输入, so that 补偿工作不依赖临时目录。
35. As an 异常处理 agent, I want 对指定版本的异常记录完成、放弃或失效, so that 重复扫描不会重复执行。
36. As an 运维人员, I want 历史异常交给事后处理, so that 每日 sync 不反复卡在同一失败项。
37. As an 运维人员, I want 远端出现新版本仍按正常日常任务处理, so that 放弃旧版本不会永久忽略该文档。
38. As an 开发者, I want 从可安装 CLI 验证阶段顺序、恢复和产物, so that 验收不依赖私有脚本或内部函数布局。

## Implementation Decisions

### 入口与整批阶段

- 唯一同步工作入口为 dogpdkb sync；独立只读查询入口为 dogpdkb status。日常默认行为是自动完成全部五个阶段。
- sync 支持 stop-after 和 resume：前者选择完成哪个阶段后停止，后者指定已有 run。阶段名为 capture、mdcompare、plan、ocr、compile；不再增加另一组顶层阶段命令。
- 默认与 knowledge 使用同一个实现。删除 knowledge 的行为分流；若保留旧参数或入口用于迁移，只能作为带弃用提示的兼容转发，不保留旧执行器或另一套默认规则。
- 独立 mdcompare、mdocr 工具仍可保留各自用途；本规格统一的是 dogpdkb 的同步工作入口，不要求删除这些工具。
- 一个阶段只有一个批次职责；允许阶段内部按文档或图片处理和保存进度，但下一阶段必须等待当前阶段结束，禁止单篇跨阶段穿行。
- 无工作量的阶段标为 skipped 后继续。阶段部分条目失败可以正常结束，将可用集合交给下一阶段。
- sync 使用现有用户级运行锁。显式停止或中断保留 run；暂停批次恢复原输入，不能静默转换成另一批次。

### capture 与下载复用

- 复用已有清单采集、稳定文档身份、标签、近期范围和下载检查点能力。标签描述远端与基线变化，不代表知识语义变化。
- 先保存扫描结果、标签和去重下载名单，再执行本阶段下载；产物仍属于同一个 capture 阶段。
- 同知识库、同文档 ID、相同远端版本并且原文文件有效时复用下载。可导入历史同步或 UAT 中具有相同证据的下载记录，不仅凭文件名、日期或文件存在判断同版本。
- 无法证明版本的历史文件可以继续作为已有基线，但不能冒充已验证的当前 raw。不得把历史 OCR 富化 Markdown 标成原始导出。
- 缺失或失效的必需文件重新获取；文件有效性检查复用现有保证或直接比较，不新增通用指纹系统。
- 保留观察版本、下载版本与成功发布版本的区别。成功下载不提前声称图谱已更新。
- 完整清单失败属于不可继续判断本次范围的阶段失败。单篇导出失败归档后不阻断其他文档；缺席标签不能从不完整清单推断为远端删除。沿用已支持的来源删除契约，不新增自动语义删除。

### mdcompare 与 plan

- mdcompare 阶段整批完成离线比较，输出每篇结果；plan 消费这些结果，不重复执行比较，不调用 OCR 或 Graphify。
- mdcompare 是减少重复工作和成本的优化，不承担日常同步的人工授权门槛。沿用已有正文比较算法及其正文/OCR范围区分，不重新实现比较器。
- 明确正文复用的来源保留已有正文知识；新文档、正文增量、缺少旧输入或比较不确定的来源，在当前完整 raw 可用时自动进入完整文档编译名单。
- REVIEW、UNKNOWN、HOLD 等旧比较状态不得因为人工审核要求永久阻断日常任务。必须区分比较不确定与当前输入不可用：前者可以完整重编译，后者归档异常，不能编造输入。
- 不建立独立审批阶段、复杂自动审批条件、逐项人工处置文件或业务语义质量用例门禁。复用现有底层输入/版本验证，但改变旧人工审批作为执行前提的合同。
- plan 输出正文复用、OCR 和编译名单、原因、输入引用以及先后依赖。元数据维护纳入同一计划，不能因正文复用而遗漏改名、搬动及来源引用维护。
- 正文复用与 OCR 独立：正文相同但图片需要处理时仍进入 OCR 名单；成功 OCR 改变编译输入时，计划允许该来源进入 compile。
- 计划允许 OCR 不完整时使用当前可用内容继续编译，不在 OCR 后生成第二套审批计划。执行阶段记录实际使用的最终输入和缺失项，不将其伪装成已完成的 OCR 输入。

### OCR 尽力完成

- OCR 阶段只处理本批计划中的图片，复用已有图片处理和缓存能力。成功结果经过现有格式和产物检查后持久保存，不做模型语义质量审批。
- 同一已验证图片内容及兼容处理配置优先复用有效成功结果，不因为重复同步主动重新 OCR；URL 相同不足以证明图片未变。
- 图片发生变化或有效结果不存在时才识别。失败、空白或不可解析的新结果不得覆盖已有有效结果；不同图片的旧结果不能当作新图片结果使用。
- 单图失败记录后继续其他图片；认证不可用、额度耗尽等全批共享原因停止本批剩余 OCR；未知错误不无限重试。
- 外部调用具有有限超时和重试，OCR 阶段具有有限总时间预算并采用可运行的默认值。时间预算耗尽后保留已完成结果，将未完成项归档，进入 compile。
- 当前阶段的计数区分成功、缓存复用、失败和未尝试项，不能把额度不足导致未执行的图片计为成功。
- OCR 补齐不是本次完成的必要条件。compile 使用正文、有效历史 OCR 和本次成功 OCR，保留未识别图片的引用。

### compile、状态与成功边界

- Graphify 继续按完整来源更新，不能将 diff 片段作为完整来源替换。编译成功的来源发布，失败来源保留旧知识和旧成功版本；不得因部分提取失败清空失败来源的既有记录。
- 不以节点数量、知识差异、业务语义问题集或人工审核作为日常发布门槛；保留输入可读、输出可解析、基本图结构和写入成功等必要的产物检查。
- 复用现有编译缓存、隔离候选和发布恢复能力，不重写 Graphify、不全量重建历史图谱。正式写入成功后才推进相应成功状态。
- 一次 run 固定本次观察、选择范围和来源版本；后来出现的远端变化交给下一批。恢复必须检查产物存在及输入仍符合原批次，不能默默把新输入塞进旧结果。
- 跨批次文档进度继续由既有规范状态管理；每个 run 的轻量状态单独保存，避免每条进度都为查询重写全量文档状态。
- 状态包括 running、paused、completed、partial、failed、interrupted；阶段另有 pending、running、completed、partial、skipped、failed 等可观察结果。
- completed 表示五阶段已结束且无未解决异常；partial 表示五阶段已结束且有归档异常；failed 表示任务无法继续。stop-after 的中间停止和主动中断为可恢复暂停；意外进程退出由 status 识别为 interrupted。
- completed、partial 和正常 stop-after 返回成功退出码；无法继续的任务返回非零；用户中断沿用中断退出语义。所有情况下均保留明确结果状态，不能单凭退出码推断所有文档成功。
- partial 属于已结束批次，不残留阻挡下一次 cron 的活动任务声明。未完成批次不允许被新任务静默覆盖；启动时明确提示恢复目标。

### 查询、日志与部署方式

- status 默认只读显示当前任务或最近批次，并支持按 run 查询及 JSON 输出。展示批次、状态、当前阶段、总数、完成/复用/失败数、开始时间、最近进展时间、耗时、停止原因和日志位置。
- sync 在阶段开始、条目进展和阶段结束时原子更新轻量状态。status 结合实际进程与运行锁判断存活，不把遗留 running 当作仍在运行；最近进展时间用于展示，不仅凭超时猜测进程已死。
- status 不恢复、重跑或推进任务；没有历史任务时正常返回无记录。watch 只需重复调用 status，不新增 watch 模式或后台监控服务。
- stdout 提供简洁批次结果，stderr 提供带阶段、进度和时间的运行信息。捕获外部工具输出时及时写入对应阶段日志；不能仅在内存中等待漫长调用结束，也不能丢弃必要错误诊断。
- 调度层不依赖解析第三方日志计算业务状态，使用自身调用结果和已保存产物更新进度。默认日志不输出 token、认证内容或文档正文。
- crontab 使用明确的程序、配置和日志位置，运行环境提供既有认证；shell 合并追加 stdout/stderr 到普通日志，日志轮转使用系统 logrotate。工具无需内置日志轮转守护或自动安装 cron。

### 持久结果、异常移交与 wash 清理

- wash 是批次工作空间，包含分页、阶段报告、plan 和临时编译文件；不能是长期原文、成功 OCR、正式语料、图谱或异常恢复输入的唯一位置。
- 有效原文和 OCR 缓存必须独立于待清理的 run 持久保存，使用已有缓存能力和配置体系，不新增一组任意环境变量。
- 每批结束前持久保存结构化结果；异常包含 run、知识库/文档 ID、来源版本、阶段、原因、图片身份及必要输入引用。共享 token 或额度错误记录为批次原因，并能枚举受影响图片。
- 历史结果可重复扫描，异常具有稳定身份并区分待处理、完成、放弃和失效。优先复用已有身份与版本，不为此新增内容指纹机制。
- 同一来源版本已归档的失败不得在每天 sync 中无限重复尝试。分别保存尝试/移交状态和真实成功状态，不能用虚假成功来避免重试。
- 新的远端版本正常参加日常同步；对旧版本的放弃只作用于该版本，不永久封禁来源。未变化远端的历史 OCR 待补交由事后 agent，而非每日任务自动重试。
- 事后处理成功后必须更新对应缓存、真实完成状态和处置结果；OCR 补齐若改变了已发布编译输入，应显式登记后续编译工作，不能声称仅写入 OCR 缓存就完成知识更新。
- 每次 completed 或 partial 结束后自动清理更早的已结束工作目录，只保留最近一次已结束批次，以及暂停/未完成批次。持久历史结果、异常输入和长期缓存不随 wash 清理。
- 清理前先完成结果归档和必要输入持久化，确认状态、缓存与异常记录不再引用待删目录中的唯一文件。清理失败记录结果，不能破坏有效知识库；下次结束时可再次清理。
- 现有历史 wash 首次整理必须盘点引用并迁移必要产物，不能直接删除整个目录。长期缓存和异常归档本次不引入自动淘汰策略，避免尚待事后处理的输入消失。

## Testing Decisions

- 沿用此前已确认的最高验收入口：可安装 dogpdkb CLI 黑盒，以临时 corpus、真实文件和外部接口替身验证；不增加只为测试使用的新接口，不以私有脚本作为产品入口。
- 复用既有采集检查点、下载复用、知识比较、OCR 兼容结果、编译候选、发布恢复和安装 smoke 测试模式。只改写被本规格明确取代的人工审批/语义质量阻断断言，其余输入完整性和故障恢复回归继续保留。
- 验证五阶段整批顺序：全部采集结束后才比较，全部比较结束后才规划，全部 OCR 结束后才编译；包括零工作量、部分失败和无更新批次。
- 验证唯一 sync 入口、knowledge 兼容行为如保留时与新入口一致、stop-after 不启动下一阶段、resume 不重复有效工作，以及用户锁拒绝并发启动。
- 验证相同版本有效原文零重复下载，跨批次/UAT有效记录复用，缺失产物和变化版本重新下载；历史富化来源不能冒充 raw，重叠标签只下载一次且不回填历史缺失。
- 验证明确定义的正文复用不重复编译；新文档、REVIEW/UNKNOWN、缺少旧输入且当前 raw 有效时自动完整编译；当前输入不可用只移交异常。图片变化不能被正文复用吞掉。
- 验证 OCR 成功缓存、结果变化和无效结果、单图错误、token 无效、额度耗尽、有限超时和阶段预算。以上情况均能结束 OCR 并继续可用集合编译，保留正确待处理数量。
- 验证完整来源输入、部分编译成功与失败旧来源保留、无效图结构或写入失败不推进成功版本、提交与状态记录之间故障恢复不重复计费。
- 验证 stage/run 状态、status JSON、暂停和崩溃识别、普通日志重定向、第三方诊断落盘以及凭证不进入输出。partial 可结束并允许下一次 cron，不能遗留全局运行阻挡。
- 验证同版本历史异常不会每天重复重试，新版本仍正常处理，重复扫描与完成/放弃/失效处置可核对，OCR 后补能登记必要编译而不伪造成功。
- 验证清理只处理指定已结束批次，保留最新 run、暂停 run、真实缓存和正式产物；清理后历史异常仍可读取必要输入，旧状态引用迁移正确，归档失败不丢输入。
- 使用保留的真实本地 Markdown 和历史下载证据做有界离线 UAT；真实服务调用、token 消耗、安装交付和生产同步分别报告。规格编写不授权恢复此前暂停任务或开始新的真实 OCR/Graphify 调用。
- 完成仓库必要门禁与隔离安装 smoke。测试判据是可观察阶段行为、产物、状态、重复调用次数和恢复结果，不是某次模型输出的节点数或语义无损。

## Out of Scope

- 常驻调度器、工作流引擎、消息队列、单篇跨阶段执行、后台 watch 服务或新的监控前端。
- 独立人工审批阶段、可配置规则平台、逐项语义审判和业务知识质量作为日常同步前置门禁。
- 重写 mdcompare 算法、Graphify 模型或图谱合并器，新增通用指纹系统、片段覆盖和事实级补丁。
- 自动安装 crontab/logrotate、部署 co.bot、发布新版本、恢复已暂停的真实任务或进行生产全量回填。
- 定时 agent 的调度、模型选择和完整自主重做实现；本规格提供其消费结果、取得输入和记录处置所需的持久合同。
- 长期缓存与异常历史的容量淘汰策略；本次自动清理范围是可安全移除的批次工作目录。

## Further Notes

- 本规格记录当前对话中已确认的产品方向，不是现有能力或已完成验证声明。
- 对本规格覆盖的无人值守 sync，旧日常知识同步规格中的默认只规划、必须人工审批、REVIEW/UNKNOWN 不可完整重编译、OCR 不在范围以及语义质量用例阻断发布等要求由本规格替代。已有比较器的独立报告含义、完整来源替换和真实成功版本记录仍然保留。
- 可用性优先允许模型语义质量差异，不允许伪造采集、OCR 或发布成功。partial 必须可见，失败不能被静默当作成功。
- 先实施和验证新合同，再迁移现有批次与入口；不得把暂停在旧实现中的 run 默认为新实现已验证可恢复的 run。
