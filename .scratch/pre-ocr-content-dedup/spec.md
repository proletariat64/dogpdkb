# OCR 前内容比较与安全复用 CLI

Status: ready-for-agent

## Problem Statement

当前 dogpdkb 根据远端时间戳、改名和目录移动选择导出文档，再把导出结果送入 mdocr。文档 ID 去重和本次 OCR 断点复用不能识别“正文实际上未变”的文档，导致重复图片下载、OCR 和后续处理。

生产只读对比已发现：同日时间戳和跨日时间戳均不能证明正文变化。新导出的原始 Markdown 与历史 OCR 富化 Markdown 不处于同一处理阶段，直接比较又会把 OCR block、图片转写和格式差异误判成业务变化。另一方面，一个数字、币种、否定词或不等号的修改可能至关重要，不能用高相似度过滤。

用户需要像 mdocr 一样可独立运行的 CLI：先快速筛出确定不变的输入，再解释其余差异；不依赖大模型，不修改输入，也不自行执行 OCR、同步发布或知识图谱编译。

## Solution

提供独立、离线、只读的内容比较 CLI，工作位置为正文导出之后、OCR 之前。命令名称暂用 mdcompare，正式发行名可在实现时确定，不影响本规范的行为契约。

按稳定文档 ID 比较“上次成功发布的原始 Markdown 与本次原始 Markdown”，采用直接字节比较、显式启用的有限规范化，以及 Myers 差异定位。图片和其他外部资源独立比较，不能仅凭 Markdown 相同或资源 URL 相同跳过整篇处理。

输出版本化 JSON 决策及可选的人读报告，分别表示文本、资源、元数据和 OCR 复用条件。仅当有足够证据时才允许跳过；未知不是相同。CLI 不替代 dogpdkb 的发现、删除判定、发布事务，也不替代 mdocr 的 OCR 执行。

首版不使用 Jaccard、MinHash、SimHash 或感知哈希决定跳过，不建设全库相似索引。

## User Stories

1. As a 同步操作者, I want 按稳定文档 ID 比较新旧版本, so that 改名或移动不会被误认成新文档。
2. As a 同步操作者, I want 快速识别字节完全相同的原始 Markdown, so that 不必对这些文本运行昂贵比较。
3. As a 同步操作者, I want 明确区分正文、图片资源与元数据变化, so that 只执行必要的下游步骤。
4. As a 同步操作者, I want 对只有名称或路径变化的文档输出元数据变更, so that 不丢失目录更新也不把它当作正文更新。
5. As a 同步操作者, I want 使用有明确契约的有限规范化, so that 可忽略经验证无意义的导出差异。
6. As a 资金产品维护者, I want 所有数字、比例、币种、比较符和否定词变化保留在差异中, so that 小改动不会被高相似度掩盖。
7. As a 资金产品维护者, I want 表格、代码、删除线、链接和 Markdown 空白语义受到保护, so that 业务规则不会在清洗时消失。
8. As a 审核者, I want 看见具体的前后差异与原因码, so that 能理解自动决策依据。
9. As a 同步操作者, I want 图片 URL 相同时仍能区分资源是否已验证, so that 原地换图不会被遗漏。
10. As a 同步操作者, I want URL 不同但图片输入相同的情况被识别, so that 地址变化不强迫重复 OCR。
11. As a 同步操作者, I want 正文变化但图片未变时得到复用建议, so that 可更新正文而不重复识别图片。
12. As a 同步操作者, I want 图片变化时仅列出变化资源, so that 支持按图片复用的下游可以减少工作量。
13. As a 同步操作者, I want 只有成功且配置兼容的 OCR 产物才被建议复用, so that 失败或过时产物不会传播。
14. As a 历史语料维护者, I want 缺失原始快照或含不明来源转写时得到不确定结果, so that 不会把真实删除误认为 OCR 差异。
15. As a 自动化调用者, I want 稳定版本的 JSON 与明确退出码, so that CLI 可被任何工作流调用而不解析终端文字。
16. As a 自动化调用者, I want 每个输入文档都有且只有一个结果, so that 不会静默丢失文档。
17. As a 运维人员, I want 非法输入、重复 ID、缺失资源和比较超限有明确诊断, so that 错误不会被当成未变。
18. As a 运维人员, I want 默认离线且不输出正文或凭证到日志, so that 比较过程不扩大数据暴露。
19. As a 同步操作者, I want 比较不更新基线或正式语料, so that 失败任务不会推进成功版本。
20. As a 开发者, I want 通过 CLI 黑盒用例验证行为, so that 实现可调整而不破坏调用契约。

## Implementation Decisions

### 组件边界

- 独立安装、独立调用，依赖离线输入清单及本地文件，不依赖运行中的 dogpdkb、Yuque 登录态或 LLM。
- 主接口为 compare 子命令，接收 baseline 清单、incoming 清单及输出位置；人读报告为可选输出。首版无需跨文档查重接口。
- 核心比较对输入只读。只允许写调用者指定的报告位置，不修改 raw、OCR block、正式语料、同步断点或基线。
- 不进行网络下载。调用方负责准备资源字节或可信不可变版本证据；仅有 URL 时资源状态为未知。
- 生产接入是后续工作，本规范不授权改变现有同步任务或自动重跑。

### 输入与身份

- 清单具有 schema 版本、文档 ID、原始 Markdown 文件引用、必要元数据、资源引用及可选 OCR 产物成功记录。版本与必需字段必须验证。
- ID 的唯一性范围为来源知识库加文档 ID，避免跨知识库数字冲突；文件名与目录不作为身份。
- 输入分别声明 raw 或历史富化内容，不允许把历史 OCR 成品隐式当作原始快照。
- 元数据至少包含名称、逻辑目录及来源引用；纯同步时间戳变化应独立呈现，不触发内容变化结论。
- 原始资源、prepared image 和 OCR block 的来源对应关系必须可追踪。prepared image 指经过验证的本地 JPEG；OCR block 指有标记且包含识别文字与 prepared image 引用的 Markdown 区域。
- 资源相等与 OCR 可复用是不同判断。原始资源字节相同仍需验证 OCR 所用 prepared image、预处理及 OCR 配置兼容性和产物可用性。没有足够来源记录时，不宣称可复用。
- 资源顺序、出现次数、标题、替代文本和链接含义不因资源字节相等而被抹掉。

### 快速过滤与比较算法

- 先按 ID 配对；长度不同可直接判为字节不同，长度相同再直接比较。字节不同不是语义变化的最终定性。
- 默认规范化为恒等变换。可选规则必须有名称、版本和适用契约，结果记录所用规则。
- 首版允许显式启用经确认的换行符统一；剥离工具元数据必须依据明确的结构和来源，不支持任意正则清洗正文。
- 不默认删除空行、行尾空格、HTML、链接、图片、标点、大小写或 Unicode 差异，不排序段落或表格。
- 使用 Myers 算法生成行级插入删除差异，对可控大小的变化区域提供字符级说明。资源上限必须显式，超限标未知，不截断后判相同。
- Markdown 结构分析用于提取资源、定位变化和保护语义，不以“渲染看起来相似”作为自动跳过规则。不能完整识别的扩展语法保留原文差异。
- 不新增持久化哈希索引。当前规模和稳定 ID 已支持直接配对比较；若后续证实存在 I/O 瓶颈，另行评估摘要索引的具体收益与一致性成本。
- 相似度算法即使未来加入，也只能提供解释、排序或候选，不得凭阈值进入跳过分支。

### 决策契约

每个 incoming 文档输出一个结果，包含身份、文本状态、资源状态、元数据状态、OCR 复用状态、动作建议、原因码及有界差异证据。状态必须区分未变、已变、新增、不适用及未知；不得把未知布尔化为未变。

动作建议为：

- SKIP_VERIFIED：原始文本逐字节相同或满足已验证规范化契约，所有相关资源已确认未变，且所需 OCR 产物成功、可用、兼容；元数据亦无需更新。无图片文档不要求不存在的 OCR 产物。
- UPDATE_METADATA_ONLY：内容及资源和所需 OCR 均满足可复用条件，但名称、逻辑路径等发生变化。调用者仍需处理引用、路径与元数据更新，不能忽略整篇。
- UPDATE_TEXT_REUSE_OCR：正文发生变化，但相关资源与 OCR 复用条件已确认成立；输出文本差异，建议重组文档而非忽略变化。
- PROCESS_CHANGED_RESOURCES：资源明确新增或变化，列出所需处理的资源，同时保留正文和元数据差异。
- PROCESS_REQUIRED：输入内容可以确定，但缺少成功或兼容的 OCR 产物等条件，仍需处理。
- UNKNOWN：缺少旧 raw、来源不明确、依赖不可验证、读取失败、输入漂移或比较预算超限等，不能安全选择上述动作。可同时保留已确认的局部变化。

新增文档不是重复项，应建议处理或明确标未知。baseline 中独有文档单列为未出现在 incoming，不推断远端删除，因为 incoming 可能只是增量集合。真正删除仍由上游同步计划负责。

### 历史基线、稳定性与输出

- 只允许基于可验证的 OCR block 标记及来源映射识别派生内容；未标记图片转写与源正文无法区分时返回未知。
- 不使用包含关系证明历史正文未变；新文包含于旧文仍可能代表真实规则被删除。
- 从后续成功同步开始保留 raw、资源字节及 OCR 来源记录，与富化输出分离。成功基线的推进由发布流程负责，不由比较 CLI 自动执行。
- 比较使用固定输入视图。文件读取失败或比较期间检测到输入变化不得产生可跳过结论；默认要求调用方提供不可变快照，不能声称文件元数据检查能抵御任意并发修改。
- 同一输入与规则产生确定性结果及稳定排序；非确定时间等运行信息不得影响动作。
- 输出包含 schema 和规则版本、分类统计、逐文档结果及错误摘要。日志不默认包含正文、认证信息或完整资源 URL；正文证据仅在显式指定的报告中输出，尽量有界，报告采用私有权限。
- 报告原子发布，异常不能留下看起来完整的最终报告。正常差异不视为执行错误。
- 退出码约定：0 为全部输入完成判定且无未知；2 为完成报告但有未知或逐项错误；1 为非法清单、无法建立身份配对或不能完整生成报告等全局失败。非零不得被调用方解释为无变化。

## Testing Decisions

- 主测试缝为独立 CLI 的完整调用：临时目录构造两份清单及文档／图片／OCR 产物，断言退出码、JSON 动作、原因码、差异与输入未变；不围绕内部函数调用次数写测试。
- 现有同步测试中临时目录、状态清单和故障注入的模式可复用；流水线测试中以 runner 替代外部程序的模式可用于将来的调用方接入，但不需要复制算法内部实现。
- 对规范化策略与差异算法的边界补充少量纯数据测试，重点仍是可观察行为。
- 必测：同文同资源跳过；改名／移动仅元数据更新；文本变而图片未变；仅图片变；无图片文档；新文档；资源出现顺序、重复次数或替代文本变化。
- 必测金融反例：0.1% 改 0.2%、100k 改 300k、允许改不允许、≤ 改 <、删除一条规则、表格单元格变化，均不能进入跳过分支。
- 必测 Markdown 反例：行末两个空格、代码缩进、删除线、HTML 表格、链接目标、未知扩展语法变化不能被默认清洗吞掉。
- 必测资源反例：同 URL 换图、不同 URL 同字节、长截图仅一位数字变化、下载资料缺失、prepared image 或 OCR 配置不兼容、成功标记存在但产物丢失。
- 必测历史反例：无 raw、仅有未标记 OCR 转写、明确 OCR block 但来源不完整；不能把来源未知的文字消失解释为确定不变。
- 必测输入和报告：重复 ID、跨知识库同数字 ID、读取错误、比较预算超限、输入变化、畸形清单、空输入、有界证据及原子输出；每个 incoming 文档恰好一个结果，分类计数守恒。
- 对相同固定输入重复执行，断言决策一致。不以某个历史样本的过滤率作为正确性标准。
- 可在固定的真实只读样本上补充验收，但不执行远端抓取、OCR 或图谱编译，不为测试重建知识图谱。

## Out of Scope

- LLM、embedding 或模型判定语义等价。
- 通过相似度阈值自动丢弃变更、全库语义聚类、跨文档合并或删除。
- 重写 mdocr、自动识别历史未标记转写、猜测图片文字是否与原文语义相同。
- 本 CLI 内下载远端文档或图片、管理认证、执行 OCR、合并语料、更新知识图谱或发布 Web。
- 当前生产任务的重试、停止、修改或状态迁移。
- 自动接入 dogpdkb 或承诺现有 mdocr 已支持按图片复用；下游接入需要独立验证能力与契约。
- 历史缺失文档回填、修改现有日期截止政策或判断远端删除。
- 将 CLI 内容比较结论宣称为业务正确性、生产上线状态或无条件语义等价证明。

## Further Notes

用户已同意“直接比较、有限规范化、Myers 差异解释、资源独立验证、未知保守处理”的方案。本规范将测试缝收敛在独立 CLI 的外部行为，不新增生产调用链测试缝。

发布成功前必须保留旧基线。短期因缺失旧 raw 导致 UNKNOWN 较多属于预期，不应用激进清洗换取更高过滤率。

首版验收目标是可靠识别确定可复用项、解释其他变化并保持输入安全，不设强制性能或过滤率指标。实现时可以报告耗时与读取量，但优化不得削弱保守边界。
