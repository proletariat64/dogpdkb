# 09: 消除正文误报并独立规划提取成本

Type: task
Blocked by: 08
Status: resolved

## Problem

用户指出短时间内2,835篇待判不符合真实业务更新量，整篇LLM重提取代价不可接受。
REVIEW不是业务变化金标准，不能映射为整篇Graphify重跑。

## Evidence before edits

- 原结果658篇REVIEW没有新增/修订的非标题正文块候选，其中552篇只有标题相关不确定性，106篇只有复用或旧侧内容缺失。
- 其余候选中的18,618个新块，在旧文已存在相同类型和规范化文字，因上下文差异未对齐。
- 独立诊断20篇观察到的差异未见新增业务事实；这是定向诊断样本，不外推全量准确率。
- 旧HTML表格与新Markdown表格、字体标签、历史显式富化边界和任意前段落继承造成误报，需有反例保护地修正。
- 现有Graphify是整来源替换，不支持直接把增量块当补丁；已有文件级缓存，不可把输入文件数等同模型调用数。

## Acceptance

- 输出独立graphify_plan，旧侧缺失、标题不明、预算或读失败不自动触发提取；无整篇回退。
- 仅具体新侧正文候选进入低成本复核清单，字符量是候选单元上界，不宣称实际token或费用。
- 根据真实证据修正表示差异和上下文误报，保留金额、关系、条件、代码、表格绑定及链接目标变化。
- 图片/OCR继续完全不参与判断；仅按显式语法边界排除富化，不评估其内容。
- 原验收产物保留，另目录重跑真实全量和固定98；不以低数量为目标编造等价或业务金标准。
- 通过有意义的反例检查和仓库门禁，不修改生产Graphify选择器、合并或知识图谱。

## Answer

技术修正已交付，业务自动重提取验收仍未达到：不能把待判或候选当作实际更新。

- 已修复有真实证据的展示/表格/继承作用域误报，并将成本计划与比较状态分开。
- 4,752篇最终计划为KEEP 2,087、HOLD 1,861、正文候选804；804仍含误报，不批准批量整篇重提取。
- 定向20篇无观察到新增事实的诊断样本中，最终14 HOLD、1 KEEP、5仍为候选；候选载荷从中间版38,660字符降为3,520字符，不能外推实际费用或全量准确率。
- 838项仓库测试、116项正文测试、离线构建及隔离安装通过；源文件逐字节保持，生产和原验收产物未修改。
- 实际LLM调用数、真实新增知识篇数尚不能从本报告确定；当前Graphify整来源替换接口也不能安全执行片段补丁。
- [修正后的业务/成本验收记录](../../../docs/mdcompare-business-uat.md)。后续需要真实事实判据验证及安全的来源单元合并契约，不能用降低阈值或整篇回退兜底。
