# 正文知识复用与增量比较

Status: implementation

## 当前目标与范围

用户最新目标是知识库不重复知识，同时保留真正新增或修订的知识。验收不再以整篇文件严格一致或可跳过数量为主。交付一个独立、离线、只读的 `mdcompare knowledge` 命令，给出知识单元复用与增量报告。

用户明确排除图片和 OCR：不读取图片，不比较图片、识别结果、OCR配置或复用证据，不生成相关任务，不设置图片待判，也不以图片/OCR缺口阻塞正文结果。忽略图片引用及明确标记的 OCR 富化区块。历史未标记混合文本无法自动恢复来源，必须说明可观察正文的范围，不能猜测原始 raw。

本规范是新命令的当前契约，覆盖[原始规格](spec.md)中关于图片、OCR和历史 raw 前置门槛的要求。原有 `mdcompare compare` 保留原始严格比较契约以兼容调用方，不将其资源/OCR动作混入新命令。

## 输入和输出

- 输入沿用版本1.0清单：知识库、文档ID、正文路径、内容阶段和元数据。知识判断忽略资源、OCR及来源证明声明；报告仍不得覆盖任何声明输入。
- 按知识库加文档ID配对；没有对应旧ID的新单元仍可复用同知识库所供基线中的匹配知识。按稳定ID顺序处理的后续incoming文档，也可复用此前incoming文档的匹配知识，来源用 `old_side: incoming` 明确区分。旧侧独有ID单列，不推断删除。
- 输出 JSON `schema_version: knowledge-1.0`、`scope: body_only`，包含逐文档结果、旧侧独有ID、统计和逐项错误。
- 每个 incoming 文档恰好一个稳定排序结果，含身份、状态、单元计数、单元列表和原因码。单元保留可用的新旧来源位置及判定依据；正文证据默认省略，仅显式启用后有界输出。
- 单元的 `body_seen_before` 表示同类型及规范化键已在同ID旧正文某处出现，`existing_body` 指向其旧侧来源位置；该事实不证明章节、主体或条件等价，不改变原有单元kind。`new_body_chars` 为该新侧单元的完整正文字符数。
- 单元的 `presentation_seen_before` 和 `existing_presentation_body` 标记有限展示匹配：未围栏包裹的受支持富HTML、或含该富HTML的表格，使用同一保守正文/表格规范化键，可匹配纯段落或表格对应物；空展示包装及全空表格正文行属于展示，不删除表头、非空行、列位置或非空行内的空单元。围栏或其他字面代码、pre/code/script/style、white-space CSS、未知XML和数值变化不参与该投影；单元kind保持不变，不作为知识等价证明。

| 单元结果 | 含义 |
| --- | --- |
| reuse | 在已实现规范化及上下文规则下，新单元由旧知识覆盖 |
| add | 没有可支持的旧侧对应单元 |
| revise | 定位到疑似修订，保留新旧依据，不作为等价复用 |
| old_only_review | 旧侧正文单元在新侧未观察到，不自动删除旧知识 |
| unresolved | 单元比较不充分或工作预算耗尽 |

文档状态为 REUSE、DELTA、REVIEW、NO_BODY 或 UNKNOWN。只有新增而无疑似修订、旧侧缺失或未判单元时为 DELTA；疑似修订、旧侧单元缺失和未判单元需要 REVIEW并返回2；读取、解码或漂移错误为 UNKNOWN。没有正文不能推断被排除内容的状态。

REVIEW篇数不是实际知识更新篇数，更不是模型重提取清单。逐文档额外输出 `graphify_plan`，使比较结果与花费决策分开：

| 计划动作 | 含义 |
| --- | --- |
| KEEP_EXISTING | 正文可复用，保留现有图谱知识 |
| HOLD_EXISTING | 没有具体新侧正文候选，或比较不完整/不可用；保留旧知识及明确缺口 |
| BODY_DELTA_CANDIDATE | 有新增、疑似修订或对齐歧义的新侧非标题单元，且其规范化文字未在同ID旧正文出现，先进行低成本检查或针对性事实确认 |

每个计划固定 `plan_only: true`、`automatic_extraction_allowed: false`、`full_document_fallback: false`。`candidate_unit_indexes` 为单元数组中的零起始索引；`context_review_unit_indexes` 单列已有文字处于变化上下文及变化标题的单元；`presentation_review_unit_indexes` 单列有限展示匹配的未复用单元。两类复核均不进入新正文候选，没有其他候选时保持HOLD，不改判为知识等价或自动复用。`candidate_body_chars` 为候选新侧单元的完整正文字符数，不是最小差异长度，也不含标题或额外上下文载荷。汇总 `summary.graphify_plan` 输出动作计数、候选正文字符数、`context_review_documents`、`presentation_review_documents` 和固定为0的 `automatic_full_document_extractions`。

文字见过不等于业务范围未变。USD章节改为EUR而规则文字不变时，保留REVIEW/HOLD及旧事实，不自动跳过该业务范围变化，也不整篇重提取。条件段落A改为B时，该段落可产生一个新正文候选，其文字不变的下属单元进入上下文复核，不反复计为新正文。

旧侧内容缺失、历史来源不明、仅标题/主体不确定、读取错误或预算未完成不默认调用模型，不触发整篇重提取。混合文档可独立保留这些问题，并列出已观察到的具体新增候选。候选不等于已确认业务变化；字符计数不等于模型tokens或实测费用节省。

当前计划只读，不接入生产同步或Graphify调用。现有Graphify调用已有文件级语义缓存，但[合并逻辑](../../src/dogpdkb/workflows/graph_sync.py)会替换受影响来源的旧记录，[更新器](../../src/dogpdkb/workflows/update_graph.py)要求完整来源覆盖，不能把变化片段直接冒充整篇提取结果。实际执行块级计划前，必须另行定义保留未变知识的单元覆盖与合并契约，不提供整篇重提取回退。

## 实现边界

1. 用章节、独立事实、列表、正文表格和代码块作为比较单元，保留原始位置和上下文。
2. 支持有明确语义边界的格式及数量单位规范化，避免把10万元和100000元当作不同事实；不得丢失主体、条件、否定、代码缩进、URL目标、表格绑定及有序步骤关系。
3. 独立事实顺序变化不必变成全篇新增；工作流顺序变化不能因词项相同进入 reuse。
4. 相似度只定位疑似修订或待判，不能单独批准知识等价。工作预算限制须显式，不能把未比较单元当重复。
5. 跨文档复用要求知识库、`metadata.name`、`metadata.logical_path`、单元类型、章节上下文和规范化单元键均相同；通用章节名不足以证明主体相同。输出规则为 `cross_document: same_book_name_path_and_unit_context`，保留实际来源文档ID、来源侧和行位置。不实现模糊跨文档检索，不宣称广泛语义召回。
6. 不调用新外部模型端点，不新增持久指纹索引，不自动合并、删除、同步、OCR、Graphify编译或发布。

## 验证与完成条件

- 完整 CLI 路径生成私有、原子报告，保留原输入；返回码0表示正文判定完成，2表示报告完整但存在 REVIEW、UNKNOWN或逐项错误，1表示清单或全局输出失败。
- 覆盖部分复用加新增、局部规则修订、事实重排、单位等价、表格值绑定变化、否定、URL目标和代码缩进变化。
- 图片及 OCR 内容变化、缺失图片/识别产物、OCR配置变化不影响正文结论，不生成额外任务。
- 历史输入缺少旧 raw 不得统一阻塞正文比较；明确标记的 OCR 区块排除，未标记来源限制如实呈现。
- 跑冻结真实文件 UAT，报告可复用、新增、疑似修订、旧侧待判和未判单元的实际数量及局限。开发合成样本单列，不冒充真实UAT或业务金标准。
- 不以候选相似度、跳过文件数、98篇人工分类或输入字节一致性替代知识层面的验证。
- REVIEW和计划动作分别计数；历史旧侧缺失、仅标题不确定或预算未知不能默认产生LLM调用。候选字符数只报告输入范围，不宣称未经实测的费用下降。

实现和真实 UAT 记录应区分已验证能力、尚待语义判断的内容及后续生产接入。用户文档见[正文知识命令指南](../../docs/mdcompare-knowledge.md)。
