# Sync 长任务故障恢复

Status: ready-for-agent

## Problem Statement

首次 co.bot 生产同步在获取语雀文档列表、生成同步计划时失败。日志显示共 151 页，部分页完成后，`skylark_doc_list` 返回 `Request timeout for 15000 ms`，计划子进程及同步主进程均以非零状态退出。该事件尚未进入正文导出阶段。

用户需要长任务在短暂故障后继续，避免重复昂贵的已完成工作，并明确知道哪些结果可以安全复用。当前错误提示主要是嵌套 traceback，未提供足够的故障范围和恢复说明。

本地代码已有阶段级恢复、逐文档导出检查点和逐文件 OCR 检查点，并非所有阶段都只能从头运行。实际缺口包括：

- 重试分类依赖少数结构化标记，普通上游超时可能被当作不可重试错误；MCP 协议错误也未统一分类。
- 列表分页文件只用于诊断；列表阶段中断后会全量重新获取，用户无法从输出理解这一限制。
- 正文导出记录个别失败后，仍会继续发布成功文档、执行删除并更新同步状态；主流程随后才依据 manifest 阻止图谱及 Web 阶段。失败检查晚于语料修改。

日志未包含完整错误 envelope、生产有效重试配置或上游诊断信息，因此不能证明超时发生于哪一个服务，也不能断言当时没有重试就是某一个具体分类分支导致。生产安装版本与本地代码的等同性尚未核验。

## Solution

让恢复粒度尽量接近失败粒度，同时保持数据完整性：

1. 对可识别的暂时性只读 MCP 故障执行有上限的退避重试；一次请求失败不立即使整个长任务失败。
2. 重试耗尽时保留有效暂存产物，返回非零退出码，报告失败位置及使用同一 staging 的恢复方式。
3. 未完成的列表阶段重新获取完整列表，不跨运行拼接 offset 分页缓存；已完成且有效的计划继续按现有恢复契约复用。
4. 在同一个固定同步计划下，正文导出和 OCR 复用已有有效检查点，只重做未完成或产物缺失的工作。
5. 任一必需导出或 OCR 工作失败时，不开始正式语料发布，不执行计划中的删除，不更新正式同步状态，不运行图谱/Web 阶段。
6. 保留已有同步范围：仅同步近期增量，不补齐历史上有意过滤的文档。

## User Stories

1. 作为同步操作者，我希望单页列表请求偶发超时后自动重试，以免一次网络波动使计划阶段失败。
2. 作为同步操作者，我希望正文详情和 TOC 等只读调用采用一致的暂时性错误处理，以免恢复在另一个 MCP 调用处再次直接退出。
3. 作为同步操作者，我希望重试有明确上限和退避，以免任务无限等待或持续冲击服务。
4. 作为同步操作者，我希望认证、权限或参数错误及时终止并给出原因，以免无意义地等待重试。
5. 作为同步操作者，我希望输出区分本地等待超时与调用链返回的超时，以免误以为修改本地超时一定有效。
6. 作为同步操作者，我希望失败信息包含阶段、工具和分页或文档定位信息，以便定位失败单元。
7. 作为同步操作者，我希望失败后保留 staging 并给出准确恢复命令，以便继续同一次任务。
8. 作为同步操作者，我希望明确获知列表阶段为何需要重新获取，以免把诊断分页文件误当成安全快照。
9. 作为同步操作者，我希望恢复复用有效的已完成计划，以免下游失败后再次获取全部列表。
10. 作为同步操作者，我希望同一计划中已成功导出的文档不重复导出，以减少远程调用。
11. 作为同步操作者，我希望已成功 OCR 的文件不重复处理，以减少耗时和费用。
12. 作为同步操作者，我希望缺失的暂存产物不会被当作已完成，以免恢复生成不完整结果。
13. 作为同步操作者，我希望未解决的导出失败不会发布半批语料或执行删除，以保护正式数据。
14. 作为同步操作者，我希望合法的空正文跳过与失败明确区分，以免正常跳过阻止同步或真实失败被忽略。
15. 作为同步操作者，我希望更换计划或不兼容配置时拒绝误用旧检查点，以免混合不同任务的数据。
16. 作为同步操作者，我希望 Ctrl-C 后保留已提交的检查点，并且重启不会把未完成任务标记成功。
17. 作为知识库使用者，我希望图谱和 Web 只使用成功完成的语料批次，以免读取因导出失败而不完整的更新。
18. 作为维护者，我希望无需真实语雀或生产环境即可重现故障与恢复，以便回归测试稳定且可重复。

## Implementation Decisions

### 1. 复用现有恢复入口

- 保持 `sync --resume --staging <原目录>` 作为恢复入口，不引入第二套任务系统、数据库或恢复命令。
- 保持已完成阶段产物校验、配置兼容性校验、固定 cutoff，以及导出检查点绑定同步计划的现有契约。
- 同一计划下复用已记录的导出版本及产物；不把恢复解释成对语雀实时状态的重新快照。后续远端变化由后续同步处理。
- 不为本需求新增内容 hash 或全局指纹系统。优先使用现有计划身份、文档 ID、记录的源版本、状态和产物存在性检查。

### 2. 统一只读 MCP 错误分类与重试

- 在现有调用适配层统一处理业务 envelope、JSON-RPC 错误以及本地传输异常，保留错误来源和可用的结构化错误码。
- 保留已有重试信号；对明确的限流、暂时性网络故障、请求超时和暂时性服务不可用增加分类，覆盖 HTTP 429、502、503、504 等可识别情形。
- 结构化信息优先；对于只有文字的响应，允许对明确、受约束的超时格式兜底，必须覆盖生产日志中的 `Request timeout for 15000 ms`。不得通过泛化的 `error` 或任意 `timeout` 子串将所有失败判为暂时性。
- 明确的认证失败、权限拒绝、参数错误优先作为不可重试错误；未知错误默认不无限重试，也不通过重试绕过认证边界。
- 复用现有最大重试次数、指数退避、抖动和延迟上限。最大重试次数指初次调用之外的次数；不在多层重复叠加重试预算。
- Ctrl-C 不作为暂时性错误重试；每次尝试均释放代理进程和连接资源。
- 本规格仅授权同步所需的只读远程调用自动重试，不扩展到远程写操作。

### 3. 列表一致性边界

- 同一次列表获取中，就地重试失败页，不因一次可恢复失败重新调用已成功页面。
- 进程退出、取消或列表获取最终失败后，下一次恢复重新获取全部列表页，并明确说明原因。
- 不复用旧 offset 页与新页拼接：远端没有快照 token，增删或排序变化可能造成漏项，单靠总数和 ID 去重不足以证明一致性。
- 保留现有重复 ID、数量不足、额外分页及删除前置检查；未完成列表不得产出可应用的成功计划。
- 不宣称一次完整遍历就等于远端原子快照；远端并发修改下的严格快照能力不属于本次承诺。

### 4. 文档及 OCR 恢复

- 保留逐文档导出、逐文件 OCR 检查点和原子替换检查点的方式。成功产物落盘后才能记录完成；重启时缺失产物必须重新生成或明确阻止恢复。
- 单个导出错误可继续收集其他文档的成功结果，但失败项不得被写成完成项；检查点必须保留其定位信息。
- 有导出失败时，可以继续准备成功文档的 OCR 暂存产物，但绝不能进入正式发布。
- 保留现有空正文语义：新文档允许显式跳过，已跟踪文档的空正文属于应处理的更新；不得将认证、超时等错误伪装成空正文。

### 5. 发布前失败检查

- 在 apply 自身开始任何正式文档替换、删除或同步状态更新前，检查必需导出与 OCR 是否全部成功或明确合法跳过。
- 有未解决失败时，保留检查点和诊断 manifest，返回非零退出码。即使直接执行 apply、或使用仅暂存模式，也不能把含必需失败的运行报告成成功。
- 主流程不得把该 corpus 阶段标为 completed，且不得运行图谱/Web；manifest 存在不等于阶段成功。
- 恢复成功后，使用整个固定计划的成功结果完成发布，不仅处理本次重试新增的成功文档。
- 保留已有发布预检、备份、逐文件原子复制和删除保护。发布已开始后若发生磁盘/进程故障，必须报告失败且不得推进下游；不得将“发布前无失败”描述成跨所有文件的事务原子性。
- 旧检查点继续通过既有有效性检查恢复；旧版本已经发布的半批结果不自动回滚，也不得宣称仍满足新版本的发布前不变性。

### 6. 运维可见性

- 重试日志提供阶段、工具、attempt/预算、等待时长，以及可用的 book ID、offset 或 doc ID。
- 最终失败摘要提供已完成/失败数量、失败单元、保留的 staging 路径，以及可执行的同目录恢复命令。
- 列表失败时明确写出“恢复将重新获取列表”；导出/OCR 失败时说明已有有效检查点将复用。
- 清晰区分本地超时和远端返回的超时；不将 15 秒值错误描述为本地配置值。
- 日志不得输出认证材料、完整生产响应或正文内容；错误消息需要有界且适当脱敏。

## Testing Decisions

用户已确认：以现有同步流程为主要测试边界，使用可控 MCP/代理响应模拟超时、失败和重启；不依赖真实语雀、生产环境或真实 OCR 服务。

- 优先复用现有 pipeline runner、apply 的导出/TOC/OCR 替身和列表测试入口。只有错误响应解码、超时分类及代理资源释放需要适配层的窄测试；不新增庞大的测试框架。
- 好的测试观察退出状态、正式文件及同步状态、暂存产物、后续阶段是否执行，以及验证恢复是否重复调用远端所需的调用记录。不绑定私有函数拆分、线程完成顺序或 traceback 文本。
- 现有先例包括：图谱失败后的阶段复用、dry-run、导出检查点复用、OCR 单文件恢复、新旧空正文处理、列表刷新不混用缓存、发布备份及删除保护。
- 时间和随机等待可控，测试不实际等待退避，也不依赖线程竞态来制造故障。

### 验收场景

1. **生产超时回归**：列表某页先返回缺少 retryable 标记的 `Request timeout for 15000 ms`，随后成功；只重试失败页，成功页不重做，计划成功生成。
2. **协议与传输分类**：envelope 和 JSON-RPC 两种可识别暂时性错误，以及本地超时、断连，均遵循同一预算；未知及明确永久错误及时失败。
3. **预算耗尽**：持续暂时性错误恰好耗尽配置预算后退出非零；不生成可用成功计划、不修改语料，并显示失败页和恢复路径。
4. **认证与权限**：认证/权限/参数错误不进入暂时性重试循环；输出可操作且不泄露凭据。
5. **列表跨运行恢复**：预置旧分页文件并改变模拟远端列表，恢复时所有页重新获取，旧页不参与新计划；保留重复和不完整列表拒绝用例。
6. **已完成计划复用**：计划完成后导出失败，恢复不重新执行计划阶段；不兼容计划或配置被拒绝。
7. **导出失败不发布**：构造至少一个成功文档、一个失败文档及一项计划删除；运行失败后，正式文档、待删文档和正式同步状态均与运行前一致，图谱/Web 未执行，成功导出仍留在 staging。
8. **导出恢复**：同一 staging 恢复后，只重新导出未完成或产物缺失的文档；全部满足条件后发布完整批次，删除及同步状态才更新。
9. **OCR 恢复**：部分 OCR 成功后失败，正式语料不变；恢复复用成功 OCR 产物，只重做失败或缺失产物，完成后才发布。
10. **空正文语义**：新空正文合法跳过不阻塞成功；已跟踪文档变空仍正确更新；暂时性错误不被视为空正文。
11. **取消与检查点**：成功保存至少一个检查点后模拟中断，未完成项不标为完成；恢复复用有效工作，释放活动代理资源。
12. **直接 apply 与仅暂存**：不经主流程调用 apply，或使用仅暂存模式，必需导出失败仍返回非零且不发布；有 manifest 不足以报告成功。
13. **发布失败隔离**：注入发布失败，确认不报告 corpus 成功、不运行图谱/Web；本测试不要求回滚已经逐文件完成的发布。
14. **输出与回归**：验证失败摘要的阶段、失败单元、重试预算、恢复命令及列表刷新说明；既有 dry-run、阶段复用、历史过滤、备份/删除保护测试继续通过。

## Out of Scope

- 修改 co.bot 生产安装、自动重跑生产任务，或写入远程语雀。
- 修改语雀/MCP 服务端超时、增加服务端快照协议，或保证远端并发编辑下的原子列表视图。
- 未有快照保障的跨运行 offset 分页续传。
- 全量历史文档补齐、重建整个知识图谱。
- 新任务调度平台、数据库、分布式队列、多进程协同恢复或跨主机迁移任务。
- 全语料/图谱/Web 的统一事务、自动回滚旧版本部分发布、抵御任意磁盘破坏的检查点系统。
- 为此次需求新增内容 hash、指纹体系或对所有已完成文档额外逐一请求远端版本。
- 独立的图谱/Web 内部恢复机制改造、性能基准或观测平台。
