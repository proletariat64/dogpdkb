# 清理哪些 wash 产物，保留哪些复用与观察能力

Blocked by: 01

## Question

成功后的清理目标是删除可丢弃的重复编译工作区并保留仍被使用的输入与记录，
还是让 wash 只剩小型记录、将必需复用输入归入持久目录？
据此明确清理后原始比较基线、OCR 复用、status 和结果产物引用应保持的行为，
以及验证这些行为所需的最小验收场景。

## Comments

- 全 run 删除会影响下一次比较基线、OCR 复用和观察记录，不能视为纯临时文件删除。
- 原始事实见 [当前 wash 的归属和引用](../facts.md)。
- 不预先决定搬迁方案，也不建立通用历史引用搬迁系统。
- 用户已明确 partial 不要求恢复原 run；后续 agent 可创建新 run 判断和处理失败。
  因而保留材料应服务于失败交接、必要复用和简要观察，而非原 run 可恢复性。
- 当前待确认的产品选择：失败交接是否只保留身份、版本、步骤、错误与小型报告，
  让后续 agent 重新获取来源；还是还需保留失败时的原始 Markdown/图片供离线诊断？
  建议前者，不承诺清理后仍可复现旧版本输入。后续同步必需的最新比较基线等
  应独立于 wash 保存，不为每个已完成 run 保留全套副本。

## Answer

用户明确要求保留失败的 Markdown 和图片，替代首轮“只留小型报告”的建议。

- 自动清理删除本次成功部分的临时副本和可丢弃的重复编译工作区。
- 失败部分保留现有的 Markdown、相关本地图片及定位失败所需的报告；
  同时保留文档身份、版本、步骤、命令、退出码或失败原因。
  原始输入未成功获取时如实记录缺失，不为保留材料而重新下载或补跑工具。
- partial 不恢复原 run；保留输入用于后续 agent 判断及创建新 run，
  不要求保留整套旧执行工作区或候选图谱副本。
- 保留简要 run 记录和结果，供 status 查询；自动清理不能让失败材料引用失效。
- 后续同步必需的最新比较基线与有效复用输入应独立于 wash 保存，
  不以保留所有成功 run 实现持久性；具体落盘布局由实现选择。
- 手动 purge 可删除所选 wash 中上述记录和失败材料；不扩大到正式语料、
  图谱、持久状态或工具缓存。清理与 purge 都不能触发隐式历史回填或失败重试。

### 验收边界

- 同一批次成功与失败文档混合：成功临时副本删除，失败 Markdown/图片/报告仍可读取。
- OCR partial 后正文和图谱成功：仍保留该失败文档的 Markdown 和相关图片，
  不因后续成功掩盖 OCR 失败。
- 下一次无变化同步和真实增量仍可使用正确比较基线与有效复用输入；
  不依赖被删除的成功 run 产物，也不重试已抑制的失败版本。
- 清理后 status 能读取简要记录；失败交接引用有效。
- 显式 purge 后只移除目标 wash；正式语料、图谱、持久状态和工具缓存不变。
