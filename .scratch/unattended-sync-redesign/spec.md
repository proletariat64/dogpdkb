# dogpdkb：可恢复的无人值守同步

Status: ready-for-agent

## Problem Statement

值班者需要定时把远程订阅或一批本地 Markdown 同步到指定知识库，无须 agent 在线。现有编排能做离线比较、可选评分和目录建图，但 OCR 逐篇启动 Paddle，下载并发和工具请求并发容易混淆。一次部分失败后，操作者需要知道哪些正文可读、图实际用了哪个版本、哪些请求可以安全续做，而不是只有一个成功或失败的退出码。

## Solution

`dogpdkb sync` 是日常入口。planner 确定本轮来源、目标、依据和动作；runner 顺序完成 collect、plan、ocr、corpus、graph，阶段内充分并行。默认不暂停；任一主阶段可作为停点。同一计划可恢复，不靠值班者审批，不重新发现输入。正文逐篇发布，图按冻结目录整批发布。失败交接给后续清理 agent，而不是作为正常同步的前置条件。

## User Stories

1. 作为定时任务维护者，我希望一次 sync 就能跑到本轮终点，不需要有人确认阶段切换。
2. 作为订阅维护者，我希望按 book 选择发布目标，按 source 选择已登记的来源，不碰未选择的来源。
3. 作为本地操作员，我希望直接指定日期目录，不改订阅配置、不安装 Skylark 就能同步。
4. 作为操作员，我希望采集或计划后可暂停，看到输入范围和拟执行动作再决定何时继续。
5. 作为读者，我希望某篇导出或 OCR 失败不妨碍阅读其他篇的新内容。
6. 作为内容负责人，我希望普通同步以确定性比较为先，只有显式开启评分才为语义打分调用模型。
7. 作为操作员，我希望整批 OCR 默认用 LLM 和一份执行计划，而不是逐篇启动工具或逐篇重置预算。
8. 作为管理员，我希望并发上限控制实际工作的那一层，不把三个子进程各自再并发三次。
9. 作为审计者，我希望分清原件、留存替代件、工具输出和发布副本，能够核验实际字节。
10. 作为断电后接手的人，我希望 resume 继续未发送工作，绝不因为缺少结果文件而重复发送。
11. 作为清理 agent，我希望按文档、版本、失败阶段和证据定位可重试项，而非重跑整本。
12. 作为值班者，我希望 watch 告诉我正在做什么、有多少项已完成以及下一步是什么，退出观察不停止同步。
13. 作为图使用者，我希望正文变新但图未追平时能看到差异，而非被部分图替换上一份好图。
14. 作为首次使用者，我希望首页帮助能教我跑、看、续，用到高级选项时才查详细契约。

## Implementation Decisions

### 输入与目标

- 保留 `sync --book BOOK` 与可重复的 `--source KEY`。新增 `sync --book BOOK --dir PATH`：本次只读该目录；目标唯一时可简写 `sync --dir PATH`。目标不唯一必须指定 book，不能由目录名推断。直接目录与来源选择互斥；resume 不接受新的目录或来源。相对 CLI 路径相对调用者工作目录解析，绑定后不随恢复时工作目录变化。
- 直接目录沿用已登记目录的递归 Markdown、资源冻结和排除规则，不修改订阅配置，不发 Skylark 请求。匹配现有来源时沿用身份；否则将本地来源与目标及规范化根目录绑定，沿用目录来源的文档身份规则。不得仅凭同名文件合并不同来源或以日期目录替换既有来源。带明确来源身份的快照只有在映射有证据时才能对账；不猜测身份或删除。未选来源不参与缺失判定。
- 区分发现、取得原件、已发布正文、成功入图四种事实；各自记录版本、实际字节见证及来源。发现版本不证明已取得正文；留存材料不标记为原件。

### 固定阶段与工具合约

| 停点 | 阶段完成时对外保证 |
| --- | --- |
| collect | 已选来源已扫描；逐篇冻结实际得到的正文与资源，记录导出失败。选定来源列表不完整时不得用它作完整发现或发布计划。 |
| plan | 输入、比较基线、目标、策略和逐文档动作已冻结；允许按配置调用评分，但尚未执行 OCR、改写正文或建图。 |
| ocr | 入选文档共用一个 mdocr plan 和结果日志，已逐篇核验并记录完成、失败、未开始或未知。无候选即跳过。 |
| corpus | 逐篇发布可用正文；保留上一代与字节见证。OCR 不完整不是 OCR 成功。 |
| graph | 无待入图内容则不启动工具；否则本轮对一个冻结目录最多一次提取，记录整体发布或保留旧图的原因。 |

- `--stop-after` 到达指定边界即持久化，前四阶段以 paused 收尾，最后阶段正常结算。阶段间不并行开多个 provider 池。runner 只通过公开 CLI 和产物集成；已有单阶段入口复用同一逻辑。
- Skylark：编排层默认同时导出 3 篇，可选 1–3。一篇失败不取消其他篇。只有工具公开区分限流才可承诺相应降档，不能从任意错误推断 429。
- mdcompare：NEW/CHANGED/UNCERTAIN 默认编译，EQUIVALENT 跳过，UNAVAILABLE 暂缓。独立的评分请求预算默认 0。仅已验证且合格的 CHANGED 证据可用有效 1–3 分改判跳过；4–5、缺失、无效、超限或结果未知保持原编译路由。保留原报告、索引、窗口与旁证。不在 runner 重写路由算法。评分的目标并发为 3，当前工具串行；并发、降档、预算受理和恢复若扩展，归 mdcompare 公共 CLI，在其支持前保持真实串行，不复制评分进程。
- mdocr：默认 LLM、OpenAI Pi OAuth、`openai/gpt-6.1-terra`、medium、并发 3；Paddle 仅显式选择。OCR 请求数默认不限（不传上限），0 禁止新请求，正整数为整批上限，独立于评分；不宣称有硬 token/金额保障。沿用原生 429 降档 3→2→1，最低档仍受限则停止派发。LLM 不可用不换模型、provider、凭据或引擎。
- 选中的冻结文档按不冲突的相对路径组成专属输入批次；业务 ID 映射另存，不改写工具报告。建 plan 前坏项可准确定位且确认未发送时，记录原因与清单修订关系，剩余文档统一建 plan；不能定位则报整批未开始，不二分试跑。有效 plan 返回部分成功时，先验证 plan 摘要和文档身份集合，再逐篇确认状态、输出、原图和 OCR 块摘要；坏项或遗漏不得冒充完成，整体绑定不可信则不采信报告。
- 工具原始 plan、result、journal、Markdown、原图和 v2 artifact 原字节长期留存；路径搬迁不得改写原件再用新 SHA 冒充。必要的链接重写仅发生在独立发布副本并记录新 SHA。清理 wash 不影响复核或恢复。
- 正文发布策略采用提案推荐默认值：OCR 未完成但有可信可读正文时发布可用正文，并记录 OCR 欠项；无可用正文保留上一版。后来补完 OCR 且产生新增内容，标为待入图，合并到下一次目录提取，不以作者正文等价为由永久跳过，也不逐篇启动 Graphify。
- Graphify 使用 patched `openai-oauth` 自有登录，不借用 Pi 或 API key。启用其原生 OAuth 并行开关和最大并发 3，不运行三个目录提取、不假设与 mdocr 相同的 429 策略。以实际入图输入、原生成功覆盖及零未解决分块为发布依据；退出 0、图变大或 JSON 可解析均不单独成立。图、manifest、cache 整体切换，失败保留旧图，不回滚正文。已知工具不能出具完整证据则不发请求；首次运行才发现则持久记录阻塞，后续不得因同一未解除原因反复发送。

### 恢复、重试、可观察性

- 同一目标单写。恢复使用冻结策略、原计划和同一执行日志，不重新发现或因配置变化重置预算。先对账：当前为预期产物则不重复写；为计划前态才可发布；其他状态为过时。正文逐篇判断，图核对整批输入及上一代。旧 run 不得覆盖新 run 已发布的版本。
- 自动续做仅限可证明未发送项。已成功不重发，已失败/未知同版本维持抑制，缺少报告不是未发送证明。清理交接记录 run、来源、文档、版本、输入摘要、阶段、发送状态、错误、证据位置及允许的重试范围；显式重试须复核见证，仅重试授权范围，不能把 v8 记录套用到 v9。若工具不支持限定范围，不放宽为整批重发。
- 状态首屏输出阶段、已完成/在途/待处理、最近进展、发布结论和下一步；JSON 与 watch 只读同一持久状态。相同来源版本但 corpus 与 graph 输入字节不同要可见。完整含有证据的策略跳过，退出 0；部分完成且有待处理项为 2；致命配置、身份或状态错误为 1；按要求暂停正常退出但状态为 paused。watch 中断仅退出观察者。
- 首页 help 只教运行、观察、恢复；子命令 help 给常用项，full help 给高级参数、证据与退出语义。doctor 只检查所选范围的配置、路径和必要入口；不嵌套调用子 doctor，不读取凭据，不作远程探测，不作为每轮同步必须经过的门槛。

## Testing Decisions

主验收面是隔离安装的公共 CLI：以临时知识库和可记录 argv、受理次数、实际最大在途数及合约产物的工具替身驱动 sync/status/resume；复用现有 orchestrator、目录来源、幂等发布、安装 smoke 和只读 help 测试。mdcompare 与 mdocr 的契约用真实本地 CLI 和模拟 provider 验证；Graphify 能力结论必须另用指定 patched 版本的公开合约及无生产数据的验收证明。断言可观察结果，不绑定内部函数。

1. 目标唯一/多目标、已登记 source/直接 dir、不同工作目录、同名 Markdown、缺本地资源与非法输入组合；本地运行 Skylark 调用数为零，不影响未选来源。
2. 五个阶段分别停/续，与不中断运行比较最终事实；修改 live 配置不改变旧计划。R1 暂停、R2 发布后再恢复 R1，不回退已更新文档或图，未冲突文档可继续。
3. 对新文档、等价、不可用、未评分、无效分及高低有效分验证路由与实际调用数；默认无评分请求。有限 OCR 额度不会因文档数、暂停而乘倍；并发计量按阶段，不拿上限充当观测值。
4. 同批 100 篇含坏项：分别覆盖 plan 前失败与执行后 99/100；一次有效 plan，认可的 99 篇不重跑。限流降档和鉴权失败不换凭据。模拟受理后断电、结果未落盘，正常恢复与下一轮均不重复发送。
5. CRLF、同名资源、留存替代件和发布链接改写；清空所属 wash 后逐字节核对原图、块、输出和报告，篡改任一见证不得复用。
6. 可读 raw 回退与后补 OCR：事实列显示具体差异；下一次集中入图，只有完整图才推进 graph。模拟图变大但遗漏分块、第二晚仍未解除阻塞：旧图不变、第二晚不重复请求；完整批次才整体切换。
7. 无 agent 的定时运行跑到终点；帮助和 doctor 不发请求；watch 可退出不杀 runner；终态、退出码和失败清单一致，可从交接记录定位单项而不需翻整本日志。

## Out of Scope

不做通用 DAG、常驻调度平台、Web 发布、工具内部算法重写、v1 OCR 迁移或自动换模型。此规格不授权实际生产 OCR、评分、Graphify 重建、删除输入、发布版本或切换生产知识库。

## Further Notes

以合并 PR #35 后的 master `7cd1480` 为设计基线。直接目录参数、整批 OCR 默认 LLM、所有主阶段停点等为目标行为，不是当前安装版保证。沿用既有订阅、状态初始化和工具合约；本规格与历史设计不同时，以这里明确列出的新行为为准。交付顺序先完成来源/阶段/恢复与状态，再完成批量 OCR 和失败交接，最后验收图完整性及发布；图能力未验证不阻塞正文链路独立交付。
