# sync 状态与现有知识库初始化设计

状态：2026-11-10 已实现于当前源码，验收见 [记录](sync-state-acceptance.md)。尚未生产部署或执行迁移。本文保留设计约束，实际 CLI 和兼容方式见 [使用指南](daily-knowledge-sync.md)。

## 范围和现有设计变更

以现有清洗 Markdown、已编译 Graphify 知识库和 books 链接配置为起点，支持 mdcompare 过滤后的增量更新。初始化不要求用户提供历史流程从未生成的 raw 登记表，不重建或重新提取已有图谱。

本设计调整状态持久化、初始化和下载选择，不改变正文比较算法、历史缺失文档不回填策略、Graphify 整来源更新及现有执行授权规则。不引入任务队列、通用工作流引擎、数据库或新的内容指纹机制。

相对 `daily-knowledge-sync.md` 的变更：已有语料可登记为历史清洗基线，不再因缺少独立 raw 登记而拒绝初始化；主状态收敛到语料目录的 `.sync-state.json`，阶段产物和计划引用该状态，不再维护另一份独立的可写知识成功状态。初始化已支持历史清洗基线；配置选定语料的知识流程使用 canonical 状态。仅显式指定旧 `--state` 且没有配置/book/input 的调用保留独立兼容模式；导入 canonical 后旧状态变成跳转标记，旧计划必须重新生成。

## 初始输入

- `graphify_flatten_ready/*.md`：当前语料，保留文档 ID、文件名日期、标题路径，以及历史富化这一来源限制。
- `graphify_flatten_ready/graphify-out/`：现有图谱、来源文件记录和 manifest。初始化只读取，不运行 Graphify。
- books JSON：知识库链接和对应语料、图谱配置。文档身份始终是知识库加文档 ID。

扫描语料时排除 `graphify-out/`、`assets/` 和工具目录，不递归把图谱报告或工具 Markdown 当正文。同一 ID 多文件登记为冲突，不由遍历顺序选一个覆盖。图谱来源对应关系优先使用现有 `source_file`，必要时按文档 ID 对齐；无法建立关系的文档标注覆盖未知，不删除原图。

## 单实例约束

同一主机、同一运行用户只允许一个 dogpdkb 数据更新进程，跨 book、配置文件和计划统一串行。锁位置固定在用户状态目录，不放在某次 staging 内，防止不同计划各拿一把锁。

使用 POSIX `flock` 非阻塞独占锁。初始化、sync、修改状态的 discover、apply、update-graph 和 publish-web 都必须经过同一个入口锁；内部子进程继承外层执行上下文，不重复争锁。只读查询、doctor 和独立 mdcompare 不受限制。子步骤仍在执行时不能提前释放锁。已有图谱发布锁继续负责图谱提交边界，不替代实例锁。

第二个更新进程直接报正在运行，不能创建新计划或改写状态。正常退出、异常或进程死亡后由内核释放锁；不靠删除锁文件或猜测 PID 解锁。初始化发现未完成计划时要求恢复该计划，不能并行推进第二个计划。

本约束不提供跨主机协调；多个主机同时写同一共享数据目录不在本次支持范围内。

## `.sync-state.json` 的职责

每篇文档记录身份、当前基线文件、文件名日期及其精度、远端观察版本、各步骤结果和待办。精确时间保存原字段、原值和统一转换后的 UTC+8 时间；不以文件 mtime、下载时间或日期零点伪造内容更新时间。

最小逻辑结构如下；books 使用配置中的稳定 key，远端 book_id 在取得元数据后另行登记。v1 精确时间迁移保留原始值：

```json
{
  "version": 2,
  "active_run": null,
  "books": {
    "fund-platform": {
      "documents": {
        "123456": {
          "baseline": {
            "file": "Example-2026-10-27-[123456].md",
            "content_kind": "historical_enriched",
            "filename_date": "2026-10-27",
            "content_updated_at": null,
            "time_precision": "day",
            "graph_coverage": "existing_source"
          },
          "observed": null,
          "steps": {},
          "pending": []
        }
      }
    }
  }
}
```

`existing_source` 表示该文档在现有图谱中有来源对应关系，不宣称已经证明图谱包含文档的全部知识。raw 来源与历史清洗来源显式区分；不把富化正文改名为 raw。

`steps` 只记录实际业务步骤的状态、输入版本和产物路径，不实现通用任务描述语言。计划、报告和 staging 中的文件仍保留，但只作为产物和恢复依据，不能独立宣告另一份成功版本。

## 每完成一步立即落盘

顺序保持为发现元数据、下载 raw、mdcompare、获准 Graphify 更新、发布。状态更新以实际产物完成为条件：

| 实际完成动作 | 立即写入的状态 | 不能顺带推进的状态 |
| --- | --- | --- |
| 取得一页有效列表 | 页覆盖、文档观察版本 | 语料和图谱成功版本 |
| 一篇 raw 下载完成 | 下载成功、详情版本、raw 路径 | mdcompare 和图谱完成 |
| 一篇 mdcompare 完成 | 输入版本、比较结果和下一步动作 | 图谱更新成功 |
| 一篇被确认正文可复用 | 比较完成及相应正文覆盖版本 | 未完成的元数据或其他待办 |
| 语料文件实际合并完成 | 当前语料路径和语料版本 | 图谱成功版本 |
| Graphify 候选生成完成 | 候选及实际提取结果 | 生产图谱已发布 |
| 图谱发布完成 | 本次实际提交文档的图谱成功版本 | 未提交文档和 Web 完成 |
| Web 发布完成 | Web 完成和产物版本 | 其他失败项 |

独立 mdcompare 仍只读；上表状态由调用它的 dogpdkb 维护。Graphify 若按批次提交，则该批文档在提交成功后一起推进；不能在候选生成或单篇提取结束时提前登记生产图谱成功。

步骤开始记录运行中；失败记录失败原因和待办。成功产物先落盘，再通过临时文件加原子替换写状态；状态写失败立即停止后续更新。启动恢复时核对已保留产物，补登记已经完成的动作，不直接重做。图谱或 Web 提交与状态写入之间的故障复用已有发布记录和恢复能力，不再建立第二套事务系统。

整次运行结束只汇总结果、关闭 active_run，不能是首次保存文档进度的时刻。观察到了新版、raw 已下载或比较待处理，都不能清掉尚未完成的图谱待办。

## 初始化已有知识库

1. 获取单实例锁，检查已有状态、未完成计划和路径冲突。
2. 按 book 扫描现有正文文件并匹配图谱来源，生成逐文档基线记录。重复 ID、无来源对应和缺文件分别记录，保留其他可用文档。
3. 从可信历史导出记录恢复精确更新时间，前提是记录确实对应当前基线文件。只有文件名日期时保留日精度，精确时间为空。
4. 现有图谱原样保留。程序完成对应关系登记，不要求全库旧 raw，不重新编译，不将历史富化正文伪装为 raw。
5. 输出初始化计数：语料数、图谱来源匹配数、精确时间已知数、仅日期数、重复 ID 和其他缺口。成功登记项落盘，冲突项留待办。

初始化可以查询远端列表，但查到的当前时间只写 `observed`。它不能证明本地旧正文对应当前远端版本，不能据此把待下载或待比较项标为完成。

## 精确时间与下载选择

远端版本优先使用 `content_updated_at`；缺少时按已有上游契约使用 `updated_at`，同时记录字段名称。创建时间仅用于新文档的日期筛选，不冒充既有文档最后更新时间。

统一默认时区为 UTC+8（固定偏移 `+08:00`）。带时区的远端时间先按其原偏移解析，再转换为 UTC+8；无时区时间默认按 UTC+8 解析，并记录使用了默认时区。保留远端原字段、原值及实际精度。状态文件、计划、报告和日志使用带 `+08:00` 的时间表示，比较时使用解析后的时间值，不直接比较不同格式的字符串。

新生成文件名的日期、cutoff、日常窗口和同日判断均按 UTC+8 取日，不依赖主机时区。已有文件名日期保留原值；历史生成时区未知时记录限制，不批量改名，也不将其补造成精确时间。例如 `2026-11-09T18:30:00Z` 转换为 `2026-11-10T02:30:00+08:00`，新文件名日期为 `2026-11-10`。

- 已有精确语料版本：远端瞬时相同且没有待办，不重复下载；远端更新则选中下载；时间倒退、缺失或字段语义改变列异常。
- 仅有文件名日期：继续使用日期作初始粗筛，同日及更新日期必须下载后经 mdcompare 判断。不能用 `>` 直接跳过同日更新，也不能直接将列表时间补成旧语料时间。
- 本地没有的 ID：沿用近期截止策略，历史有意过滤文档不回填。
- 已下载同一详情版本的 raw：恢复时复用该 raw，不重复下载；即使远端时间不再变化，未完成的比较、图谱和发布任务仍继续。
- 列表与详情版本不同：分别保存，不把它们伪造为同一原子快照，按现有异常规则处理。

第一次从日精度基线升级，可能仍需下载同日及更新日期的文档。完成下载立即保存精确详情版本，mdcompare 完成后再记录复用或变化结果；下次恢复和同日增量检查不再退回文件名日期比较。

## 兼容与验收

旧 `.sync-state.json` v1 若有精确 `content_updated_at`，迁移时保留；未记录的信息保持未知。已有清洗文件作为历史基线可进入 mdcompare 正文比较，沿用 OCR 区域排除和未知边界处理，不把 UNKNOWN 自动当成变化或复用。已有执行审批及质量条件保持原要求；本设计不新增人工登记历史 raw 的步骤。

验收使用真实文件，并覆盖：

- 仅三类初始输入即可完成登记；图谱字节不变，无 Graphify 提取调用。
- 初始化不伪造精确时间；重复 ID 不被静默覆盖，未匹配来源不丢失。
- 下载和比较部分成功后中断，已完成状态仍在；恢复不重复下载已保存版本。
- 同一天两次真实更新能被精确时间识别；同一瞬时的 UTC 和 UTC+8 表示不制造更新。
- 跨 UTC 日期边界时，文件名日期、cutoff 和窗口统一按 UTC+8；更换主机时区不改变结果；无时区输入使用 UTC+8 并记录默认来源。
- 下载成功但图谱未完成，下次仍处理图谱待办；远端观察更新不吞掉待办。
- 同用户两个更新命令、不同 book 和不同配置不能同时更新计划；子进程未结束时仍持锁。
- 图谱提交后、状态写入前故障可恢复，不重复提取或误报全部成功。

源码与隔离安装验收不代表生产数据迁移。真实文件验收仅在任务拥有的副本生成状态，未对原生产语料或图谱执行同步、迁移或提取。
